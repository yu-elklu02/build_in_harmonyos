## 编译步骤

igmpproxy 0.4 uses autotools (configure.ac, Makefile.am, autogen.sh) but
the source tarball does not include pre-generated configure/Makefile.in files.
On OHOS, automake is not available, so the conanfile.py uses direct CC compilation:

1. Download source tarball from GitHub
2. Apply patch: 0001-src-os-linux.h.patch (add _UAPI_LINUX_IN_H guard)
3. Create config.h manually (normally generated by autoheader)
4. Symlink src/os-linux.h → src/os.h (normally done by configure AC_CONFIG_LINKS)
5. Compile all .c files with clang
6. Link into igmpproxy binary

## 遇到的问题与解决方案

| # | 问题 | 根因 | 解决方案 |
|---|------|------|----------|
| 1 | sockaddr_storage redefinition | OHOS kernel headers use _UAPI_LINUX_IN_H guard, not _LINUX_IN_H | Add #define _UAPI_LINUX_IN_H to os-linux.h |
| 2 | config.guess fails on OHOS | uname -s returns "HarmonyOS", not recognized | Modify config.guess to map HarmonyOS to linux-gnu |
| 3 | config.status mktemp fails | SELinux blocks creating files in mktemp subdirectories | Use TMPDIR workaround (not needed in conan build) |
| 4 | automake not available | OHOS only has autoconf, not automake | Use direct CC compilation in conanfile.py |

## 源码修改

## 注意事项

- igmpproxy is a network daemon (IGMP multicast routing). It requires root privileges
  and network access to function. The test only verifies the binary runs.
- The build does not use autotools configure/make because automake is unavailable on OHOS.
  Instead, the conanfile.py compiles source files directly with CC.
