# E269 — Python 2 测试 runner 在 OHOS Python 3 环境中无法执行

## 错误特征

运行上游测试 runner 时出现以下任一症状：

```text
SyntaxError: Missing parentheses in call to 'print'
```

或脚本以 `#!/usr/bin/env python2` 作为 shebang，而 OHOS CI Worker 仅提供 Python 3。常见 runner 使用 `subprocess.check_output()` 调用已构建的目标二进制，再将输出与文本或 JSON 语料进行比较。

## 触发条件

- 构建系统：CMake、Autotools、Meson 或其他能够生成目标测试二进制的 C/C++ 项目。
- 阶段：测试阶段。
- 前提：上游 runner 不依赖 Python 2 C 扩展、Python 2 专有第三方包，也不依赖复杂的 `unicode`/`str` 兼容语义。

## 根因分析

部分上游项目保留 Python 2 编写的测试 runner。HarmonyOS CI Worker 提供 Python 3，直接执行会因 Python 2 的 `print` 语句等语法失败。即使 runner 已能启动，Python 3 中 `subprocess.check_output()` 返回 `bytes`；错误路径直接打印该对象会降低日志可读性。

该问题属于测试基础设施兼容性，不应通过删除或跳过上游语料来规避。迁移时必须保持测试语料、参数构造、期望值和断言比较逻辑不变。

## 解决方案

### 推荐方案

1. 审查 runner 的导入、Python 2 专有 API 与文本处理方式，确认其可安全迁移。
2. 将 shebang 改为 `python3`，将 Python 2 `print` 语句改为函数调用。
3. 保持成功路径的 JSON 或文本比对逻辑不变；仅在错误展示路径将 `bytes` 显式使用 UTF-8（替换非法字符）解码。
4. 先执行 Python 3 语法校验，再使用构建目录的动态库路径运行完整上游语料。
5. 将 runner 执行加入配方的 `build()` 或项目的正式测试步骤，避免只在临时调试阶段执行。

```bash
python3 -m py_compile run_tests.py
LD_LIBRARY_PATH=<build_folder> python3 run_tests.py
```

### 实证案例

`docopt.cpp/0.6.3` 的 `run_tests.py` 仅使用标准库 `re`、`sys`、`json` 和 `subprocess`，迁移 shebang 与打印语法后，在 OHOS 6.0 / armv8 / Python 3.12.9 上执行上游 `testcases.docopt` 的 175 条语料，输出：

```text
PASS (175)
```

### 回退方案

如果 runner 使用 Python 2 C 扩展、Python 2 专有第三方包或复杂 `unicode`/`str` 语义，不能只靠语法替换迁移。应保留上游语料不变，执行可独立运行的核心目标测试，并在适配报告中如实列出未执行范围、阻塞依赖和后续迁移计划。

### 禁止做法

- ❌ 删除、改写或标记跳过上游 `testcases` 语料以规避 Python 2 问题。
- ❌ 只验证 runner 能被 Python 3 解析，而不运行完整语料。
- ❌ 在不检查第三方依赖和 Python 2 语义差异的前提下机械使用 `2to3` 并宣称测试等价。

## 验证

```bash
python3 -m py_compile <runner.py>
LD_LIBRARY_PATH=<build_folder> python3 <runner.py>
# 确认 runner 输出的通过数等于完整上游语料总数
```

## 适用范围与边界

适用于通过 `subprocess` 调用目标二进制、比较文本或 JSON 预期结果的 Python 2 测试 runner。对 Python 2 C 扩展、`urllib2`、`unicode`/`str` 语义、Python 2 专有第三方包或网络依赖测试，需要先进行针对性的兼容性评估。
