# E301 - Conan `CMake.test()` and `CMake.ctest()` route arguments differently

## Symptom

A Conan 2 recipe builds every CMake test executable, then fails before CTest
starts:

```text
cmake --build <build-folder> --target test --output-on-failure
Unknown argument --output-on-failure
```

The defect may remain hidden on a cross-build host when the recipe guards test
execution with `can_run()`.

## Root Cause

`CMake.test()` invokes the build system's `test` or `RUN_TESTS` target. Its
`cli_args` therefore belong to `cmake --build`. `--output-on-failure` is a
CTest option, so CMake rejects it before the test target runs.

`CMake.ctest()` directly invokes `ctest` and routes `cli_args` to the correct
command. Conan 2.29.1 source code confirms the two separate call paths.

## Fix

Run CTest options through `CMake.ctest()`:

```python
cmake = CMake(self)
cmake.configure()
cmake.build()
if can_run(self):
    cmake.ctest(cli_args=["--output-on-failure"])
```

Do not pass CTest flags to `CMake.test(cli_args=...)`. If a recipe deliberately
uses the build system's `test` target, keep `CMake.test()` but pass only options
accepted by `cmake --build` and the underlying build tool.

## Verification

Run the recipe where `can_run()` is true and require both the exact CTest
command and real test results in the log. For iir1 1.10.0 on HarmonyOS PC,
both shared and static package builds emitted:

```text
RUN: ctest --parallel 20 --output-on-failure
100% tests passed, 0 tests failed out of 8
```

The package consumer tests then ran 46 independent API commands successfully.
