# E216: b2 子编译器在 OHOS 真机上的中断诊断

## 状态

路径 B 草稿。该条目只定义诊断边界，不把未归因的编译中断标为通过或平台跳过。

## 问题

大型 Boost.Test b2 构建中，b2 可能在 clang++ 输出警告后、诊断收尾前报告编译失败，并级联跳过依赖目标；相同 clang++ 命令直接执行却成功。该现象可能与设备内存/cgroup 限制有关，不能仅凭截断日志认定为 OHOS 源码或 API 限制。

## 诊断流程

```sh
b2 -j1 <target> 2>&1 | tee <target>-b2.log
# 从 b2 日志提取完整 clang++ 命令后原样直接执行
<exact-clang-command> 2>&1 | tee <target>-direct.log
```

只有在收集到完整退出信号、设备资源信息和可重复结果后，才能决定是否需要进一步的 OHOS 适配。未完成归因前，目标保持 FAIL，不得登记为 SKIP。

## 与 E074 的区别

E074 处理 GNU make jobserver/FIFO 导致的并行构建问题；本条目处理 b2 子进程与资源压力的诊断，不能用 `-j1` 的一次成功替代完整证据。
