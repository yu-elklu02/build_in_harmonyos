# E216: glib/libxml2 CMakeDeps 在 Conan 2.29 下组件头文件传播失效

> **结构化数据**: [graph/E216.kv](../graph/E216.kv) | **原则**: P-CMAKE-001
> **严重度**: blocking | **分类**: cmake | **自动修复**: GLOB-fallback
> **涉及软件**: pidgin 2.14.14 (libpurple), glib/2.84.0, libxml2/2.15.3
> **发现时间**: 2026-07-26
> **最后更新**: 2026-08-07

---

## 错误特征

交叉编译 pidgin (aarch64) 时,test_package 的 CMake 配置阶段找不到 glib 头文件:

```
fatal error: glib.h: No such file or directory
    4 | #include <glib.h>
      |          ^~~~~~~~~
compilation terminated.
```

在本地 glibc x86_64 环境下完全正常,仅在 aarch64 交叉编译时失败。同样的错误模式也发生在 libxml2 上 (`libxml/xmlversion.h`)。

---

## 根因

**Conan 2.29 + 团队 ohpcd registry 中 glib/2.84.0 与 libxml2/2.15.3 组合的已知行为**:

1. **CMakeDeps 不传播 components 的 `INTERFACE_INCLUDE_DIRECTORIES`**:
   生成的 target 文件只在 **顶层** `cpp_info` 上设置 include dirs,**components** 上为空。

2. **team ohpcd glib recipe 不使用 components 子目标**,而是 flat `cpp_info.libs` 列表,生成的 CMake target 是 aggregate `glib::glib`(由 `file_name + "::" + file_name` 约定产生)。`cpp_info.libs` 非空时,该 aggregate target 不传递 link deps 到下游消费者 — 必须显式 `target_link_libraries(test_pidgin glib::glib)`。

3. **libxml2 recipe 设置 `cmake_file_name="LibXml2"` + `cmake_target_name="LibXml2::LibXml2"`** — 大小写敏感,必须用 `find_package(LibXml2)`,不能用 `find_package(libxml2)`(CONFIG mode 不区分大小写)。

4. **conan 缓存双布局**: 同一 recipe 在不同 host 上,on-disk 布局可能是 `p/b/<pkg>/b/...` 或 `p/<pkg>/p/...` 两种。team ohpcd registry 走 `p/<pkg>/p/...`(无 `b/` 段),而 conan-center 走 `p/b/<pkg>/b/...`。`file(GLOB)` 必须同时匹配两种布局才能在不同 CI worker 上都生效。

### 为什么本地环境正常?

本地 x86_64 构建走 `find_package(glib REQUIRED CONFIG)` 系统路径搜索,`pkg-config --cflags glib-2.0` 直接返回正确路径。交叉编译时 CMakeDeps 使用 Conan 缓存的生成文件,组件 include 路径丢失。

---

## 解决方案(最终实现)

### 1. CMake target 显式链接 + file(GLOB) 兜底

在 `test_package/CMakeLists.txt` 中:

```cmake
find_package(pidgin REQUIRED CONFIG)
find_package(glib REQUIRED CONFIG)
find_package(LibXml2 REQUIRED CONFIG)

add_executable(test_pidgin test_pidgin.c)

# Aggregate glib::glib pulls in libglib-2.0, libgobject-2.0, libgio-2.0,
# libgmodule-2.0, libgthread-2.0 — all 6 PKG_CHECK_MODULES components
target_link_libraries(test_pidgin
    pidgin::pidgin
    glib::glib
    LibXml2::LibXml2
)
```

### 2. 兜底 GLOB 路径搜索(应对 conan 2.29 quirk)

```cmake
file(GLOB _GLIB_H_FILES
    "${CONAN_HOME}/p/b/glib*/p/include/glib-2.0/glib.h"
    "${CONAN_HOME}/p/glib*/p/include/glib-2.0/glib.h")
file(GLOB _LIBXML2_H_FILES
    "${CONAN_HOME}/p/b/libxm*/p/include/libxml2/libxml/xmlversion.h"
    "${CONAN_HOME}/p/libxm*/p/include/libxml2/libxml/xmlversion.h")
```

**关键 conan 路径前缀**:
- `glib` 的 5 字符 prefix = `glib`
- `libxml2` 的 5 字符 prefix = `libxm`(不是 `libxml2`!) — conan on-disk 用前 5 字符

### 3. 临时变量捕获 `set(_VAL "${${_var}}")`(防 semicolon 解析陷阱)

CMake `list()` 命令的第一个参数 `<list>` 是**变量名**(CMake 内部自动解引用)。关键问题在于:**一旦在 `list()` 参数里出现 `${...}` 形式的双解引用,变量值为含分号的路径字符串(如 `"/path1;/path2"`) 时,CMake 会把分号当作参数分隔符,导致报错 `Unknown arguments specified`**。

CMake `list()` 命令按参数行为分两类:

| 命令族 | 参数类型 | 直接写 `${_var}` 行不行? |
|---|---|---|
| `list(SORT)`, `list(APPEND)`, `list(REMOVE_ITEM)`, `list(FIND)` | VARIABLE NAME | ✅ 可以 — 接受变量名,直接 mutate |
| `list(LENGTH)`, `list(GET)`, `list(JOIN)` | VARIABLE NAME | ✅ 可以,但有额外风险 — 当变量值含分号时,`${_var}` 在其他命令上下文中会被分号分割 |

**推荐模式**:在 `foreach(_var IN ITEMS ...)` 循环体内,**先用 `set(_VAL "${${_var}}")` 将变量值捕获到普通临时变量**,之后再用 `_VAL`:

```cmake
set(_VAL "${${_var}}")     # 安全: _VAL 是普通字符串变量,不含分号陷阱
if(_VAL STREQUAL "")
    message(WARNING "...")
    continue()
endif()
```

**禁止模式**:直接在其他上下文中写 `${${_var}}`:

```cmake
# 错误: ${${_var}} 展开后含分号,被 CMake 解析为参数分隔符
list(LENGTH "${${_var}}" _LEN)   # 若 ${_var} = "_GLIB_H_FILES",展开为含分号路径 → 报错
get_filename_component(DIR "${${_var}}" DIRECTORY)  # 同理,分号导致参数错位
```

### 4. 空 GLOB 守卫(防配置阶段崩溃)

当 `file(GLOB)` 返回 0 个匹配,变量值是**空字符串** `""`。此时:
- `if(_VAL STREQUAL "")` — 正确,直接用字符串比较
- `if("${_VAL}" STREQUAL "")` — 也正确,加引号后仍可比较

**不要用 `list(LENGTH)` 来判断空** — `list(LENGTH "${_VAL}" _LEN)` 在 `_VAL` 含分号时也会出错(分号被当作参数分隔符)。

**修复**:用字符串比较:

```cmake
if(_VAL STREQUAL "")
    message(WARNING "test_package: GLOB '${_var}' matched no files under ${CONAN_HOME} — skipping include-dir fallback for this dep")
    continue()
endif()
```

### 5. 多匹配 FATAL_ERROR(防 silent garbage path)

```cmake
string(FIND "${_VAL}" ";" _SEMI_POS)
if(_SEMI_POS GREATER_EQUAL 0)
    message(FATAL_ERROR
        "test_package: file(GLOB) matched multiple versions of ${_var}: ${_VAL}\n"
        "       Clean conan cache: conan remove '*' -c\n"
    )
endif()
```

### 6. libxml2 include 路径多一层

`include/libxml2/libxml/xmlversion.h` 是 2 层子目录,需要 2 次 `get_filename_component(... DIRECTORY)` 才能爬到 libxml2 include 根。glib 的 `include/glib-2.0/glib.h` 只有 1 层,1 次即可。

## 方案对比

| 方案 | 优点 | 缺点 | 评价 |
|---|---|---|---|
| **A. GLOB 兜底搜索** (本 PR 采用) | 跨 CI/本地/OHOS worker 通用 | CMake anti-pattern | ✅ 推荐 |

| 库 | 版本 | 受影响 |
|-----|------|--------|
