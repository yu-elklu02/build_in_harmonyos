# E271 — 单文件 release 资产被误判为压缩归档


## 错误特征

初始化流程对没有归档后缀的官方 release 资产执行 gzip/tar 解压，出现：

```text
解压失败: not a gzip file
tar: Not tar
```

## 触发条件

- 构建系统：custom / 单文件脚本或可执行程序
- 阶段：init-build
- 上游下载 URL 指向无压缩单文件，且 URL 不以 `.tar.gz`、`.tar.xz`、`.zip` 等归档后缀结尾

## 根因分析

上游发布物本身是可直接执行或安装的单文件，而通用初始化器根据 URL 后缀推断格式；无法识别时回退为压缩归档。后续流程因此把普通文件交给 gzip 或 tar，解压必然失败。该错误不表示下载损坏，必须先用发布方 SHA256 和文件内容确认资产真实形态。

## 解决方案

### 推荐方案

将软件建模为 Conan `application` 和 custom 构建：

1. 使用官方 release URL 和发布方 SHA256。
2. 在 `source()` 中用 `conan.tools.files.download()` 下载指定文件名，不调用 `get()` 或解压函数。
3. 在 `build()` 中执行适用于该文件的直接验证，例如脚本语法检查和版本输出。
4. 在 `package()` 中复制到 `package/bin` 并设置可执行权限。
5. 让 `test_package` 实际执行打包后的命令及核心功能。

```python
download(
    self,
    url=source["url"],
    filename="tool",
    sha256=source["sha256"],
)
```

### 回退方案

仅当上游为同一版本另行提供权威源码归档时，才可改用该官方归档及匹配的构建配方；切换前必须核实 URL 和 SHA256。

### 禁止做法

- ❌ 不要把单文件伪装成 Autotools、CMake 或 C/C++ 项目。
- ❌ 不要跳过 SHA256 校验。
- ❌ 不要对已确认的普通文件调用 tar、gzip 或 `get(strip_root=True)`。
- ❌ 不要把 CI 自动注入的代理或镜像 URL 固化到 `conandata.yml`。

## 验证

```bash
sha256sum tool
bash -n tool
bash tool --version
```
