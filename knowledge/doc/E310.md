# E235: CLI 版本测试不得臆测品牌前缀

## 现象

软件已经完成构建、安装和打包，`<tool> --version` 也以退出码 0 输出正确版本，
但 Conan `test_package` 或 CI smoke 明确报“missing product/brand prefix”。日志中的
实际输出可能只有合法的纯版本号，例如 `1.3`，而测试额外要求出现产品名或品牌文本。
普通的 `version mismatch: expected=1.3, actual=1.4` 不属于本模式。

## 根因

消费者测试把常见展示形式当成了生产者契约。不同工具的 `--version` 输出没有统一
格式：有些输出“产品名 + 版本”，有些只输出版本号，还有些把描述写到 stderr。
若未查阅目标版本的上游文档、测试或实现，就硬编码品牌前缀，测试验证的是猜测而
不是被测软件的行为。

Cling 1.3 的上游 `Interpreter.cpp` 明确让 `--version` 只输出 `CLING_VERSION`。
Build #8914 中包内命令因此合法输出 `1.3`，旧测试却同时要求 `cling` 与 `1.3`，
在真实 JIT smoke 之前制造了假失败。

## 修复

1. 从目标版本的上游文档、测试或实现确认 `--version` 的输出位置和格式。
2. 保存原始输出和退出码，避免管道或摘要吞掉真实失败。
3. 只做契约允许的规范化，例如去除行尾换行和首尾空白。
4. 将解析结果与包管理器已解析的期望版本比较。纯版本契约应精确比较纯版本号；
   固定前缀契约则按上游格式解析，不能凭经验添加产品名要求。
5. 多格式输出只有在上游明确支持时才能兼容；无法得到唯一版本时保持失败。

不要用模糊的“包含产品名且包含版本号”同时代替格式契约和版本比较。它既可能拒绝
合法输出，也可能放过含有期望字符串但实际版本错误的文本。

## 验证

Cling 1.3 的消费者测试把去除首尾空白后的命令输出与 Conan 解析出的依赖版本精确
比较。fresh r3 签名 package 的输出为 `1.3`，版本入口为 1/1，后续 52 个独立功能
smoke 为 52/52，总计 53/53；最终日志 SHA-256 为
`e5d14f132b786dca0139db51fbd71af3970676b5be98787ec04271781c56d34a`。
定向负向验证仍应至少覆盖：合法纯版本通过、错误版本失败、品牌前缀文本失败。当前
修复提交后的正式 CI 尚待新 HEAD 执行，不能用本地真机日志替代 CI 结论。

知识匹配还要验证两条负例：普通版本不匹配不得命中本条目；只检查版本相等且没有
品牌要求的消费者也不得命中。本条目只接收明确出现 product/brand prefix 要求的失败。
