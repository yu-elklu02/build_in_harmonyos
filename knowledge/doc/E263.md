# E263: Package tests must resolve runtime helpers from the installed layout contract

> **Contributor**: 2301_80739235 | **Status**: Verified | **Updated**: 2026-08-08
> **Severity**: 2 | **Category**: packaging / installed-layout / test-helper / python / native-image

## Symptom

A transaction test passes against source files but fails when the wrapper
argument is the installed `bin/native-image.py`. The missing path is
`bin/native_image_finalizer.py`, even though the package intentionally installs
the finalizer under `libexec/graalvm-ohos/`.

## Root Cause

The test helper encodes the source layout instead of the runtime contract. A
sibling lookup is correct for direct source tests, but the installed wrapper
derives `JAVA_HOME` and loads private support from a `libexec` subtree. The
package is correct while the test's resolver is incomplete.

## Fix

1. Try the wrapper's sibling helper for source-tree tests.
2. Load the wrapper and use its own runtime-root or `_java_home()` contract.
3. Search `JAVA_HOME/libexec/graalvm-ohos/native_image_finalizer.py` for the
   installed package.
4. Report all candidate paths when neither layout resolves.

## Forbidden Shortcuts

- Do not copy the private helper into `bin/` solely for the test.
- Do not skip the packaged consumer flow because the source test passes.

## Validation

GraalVM 25.0.3 implements this in
`archives/g/graalvm/25.0.3/test_package/native_image_transaction_test.py`; the
packaged finalizer remains under `libexec/graalvm-ohos/` in PR #3928.
