## 通用问题
包可以同时安装工具和库，但 `package_type` 应反映公开消费契约。公开库存在却按 application 发布时，生成 target 可能缺链接库；默认 include 路径也可能不存在。

## 错误指纹
`undefined symbol: <public API>`、`set(<pkg>_LIBS_RELEASE )`、CMake target references non-existent include directory。

## 根因模型
包内文件存在不等于契约正确。完整链条是 package type → options → libs 顺序 → system_libs → includedirs → bindirs → generated target → consumer compile/link/run。

## 适用范围
Conan 2 中同时安装 CLI 和静态或共享开发库，且使用 CMakeDeps/PkgConfigDeps 的项目。

## 不可泛化边界
不是所有带库文件的 application 都应改成 library；内部实现库不承诺 API 时应保持 CLI-only。具体库名、顺序和系统依赖不能跨库复制。

## FAIL→修复→PASS
Poly/ML Round 13 包内静态库存在，但生成数据 libs 为空，真实 imported-target consumer 报 undefined symbol；改为 library 契约并补齐 shared、libs、system_libs、`includedirs=[]`、bindirs 后 Round 14/16 通过。日志 SHA-256：`d7663a2dcd5d1db1f87491844ef7c2cf12463218ffad1b233454c32318d377c6`。

## 禁止模式
禁止 test_package 硬编码包路径、`-L`、`-l` 或直接库文件；禁止只检查 `.a/.so` 存在；禁止盲填 libs/system_libs/include；禁止因存在 CLI 就忽略公开库契约。

## 证据来源
Round 13 FAIL、Round 14/16 PASS、CMakeDeps 生成数据和真实消费者 marker。
