# E305 — 字体/资源型数据包在 OHOS 上的适配与验证方法

## 背景

字体资源型数据包（如 OTF/TTF/woff2 字体）与传统的 C/C++ 库有本质区别：
- 无 build 步骤（no compilation）
- 无 shared/static library
- 无 include headers
- 无可执行测试用例
- 安装路径为资源目录 `share/fonts/OTF/` 而非 `lib/` 或 `bin/`
- 验证重心在：文件完整性、sha256 版本固定、OpenType metadata 正确性、Unicode 覆盖

现有 OHOS Conan recipe 知识库主要覆盖 C/C++ 库的编译、链接和测试问题，未完整覆盖字体资源型数据包的方法论。

## conanfile.py 标准骨架

```python
class OtfAtkinsonConan(ConanFile):
    name = "otf-atkinson"
    version = "1.006"
    package_type = "application"
    settings = "os", "arch"
    def layout(self):
        basic_layout(self)
    def source(self):
        get(self, **self.conan_data["sources"], strip_root=True)
    def build(self):
        apply_conandata_patches(self)
    def package(self):
        copy(self, "*.otf",
             src=os.path.join(self.source_folder, "fonts", "otf"),
             dst=os.path.join(self.package_folder, "share", "fonts", "OTF"),
             keep_path=False)
        copy(self, "OFL.txt", src=self.source_folder,
             dst=os.path.join(self.package_folder, "licenses"), keep_path=False)
    def package_info(self):
        self.cpp_info.resdirs = ["share/fonts/OTF"]
        self.user_info.font_dir = "share/fonts/OTF"
```

## test_package 验证项

1. **License 验证**：OFL.txt 文件存在且可读
2. **文件名与 sha256 验证**：4 个 OTF 文件名与 sha256 精确匹配（版本固定）
3. **OpenType name table 验证**：Name ID 1/2/4/5/6
4. **cmap 覆盖验证**：ASCII 字母、数字、常用符号
5. **安装路径验证**：`share/fonts/OTF/` 目录存在

OTF 解析器使用 Python `struct` 模块自实现，不依赖外部工具。

## 上游测试核验

字体项目通常无传统测试用例（0/0 N/A）。核验方法：遍历上游源码目录清单，确认无任何可执行测试入口后，记录核验证据。

## 禁止做法

- ❌ test_package 硬依赖 `otfinfo`/`ttx`/`fonttools`/`fontconfig`
- ❌ 把 `fc-scan`、`otfinfo`、`fontbakery` 等工具的源码混入当前 PR
- ❌ 字体项目写虚假测试通过率（应写 0/0 N/A）
- ❌ 把 `fonts/ttf/` 或 `fonts/webfonts/` 安装到 `share/fonts/OTF/`
- ❌ 在 `package_info()` 中暴露 `libs`、`includedirs`、`bindirs`
