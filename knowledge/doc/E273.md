# E273 — PETSc 安装元数据保留不可重定位的构建路径

## 错误特征

SLEPc configure 找不到 PETSc 安装，或 make 报 `petscvariables` 路径不存在。PETSc 元数据中还可能记录发布 worker 上不可用的 Python 绝对路径。

## 触发条件

- 构建系统：PETSc 风格 Python configure + GNU make
- 阶段：configure、make
- 场景：从 Conan 制品仓下载 PETSc 二进制包后构建 SLEPc 等消费者

## 根因分析

PETSc 安装目录中的 make、pkg-config 和 Python 元数据保留了构建时的绝对前缀及解释器路径。Conan 下载后的包目录与发布 worker 的构建目录不同，消费者继续读取这些路径时会访问不存在的文件。

## 解决方案

### 推荐方案

在消费者的私有构建目录中复制 PETSc 包，仅对副本中的 UTF-8 文本元数据进行重定位：将记录的 `PREFIXDIR` 替换为副本目录，并将不可用的解释器路径替换为当前 Python。不得修改 Conan 缓存，也不得对静态库等二进制文件执行文本替换。

### 禁止做法

- ❌ 直接修改 Conan 缓存中的 PETSc 包
- ❌ 对 `.a`、`.so` 等二进制产物执行字符串替换
- ❌ 在消费者配方中继续硬编码发布 worker 的绝对路径

## 验证

```bash
grep -R "PREFIXDIR\|PETSC_DIR\|python3" "$PETSC_DIR/lib/petsc/conf"
conan create archives/s/slepc/3.25.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
