# E246: HarmonyOS seccomp 拦截 Linux 私有 syscall（adjtimex 等），进程因 SIGSYS 终止

> **Contributor**: junshi_liu | **Status**: Verified | **Updated**: 2026-08-04
> **Severity**: 2 | **Category**: kernel / syscall / compat / security / seccomp

## 错误特征

进程收到 `SIGSYS` 信号（signal 31）并 core dump（exit 159），`siginfo_t` 中：
- `si_signo = 31`（SIGSYS）
- `si_code = 1`（`SYS_SECCOMP`，seccomp 过滤器触发）
- `si_syscall = N`（被拦截的 syscall 号，如 adjtimex 在 aarch64 上为 171）

## 与 E051/E164 的区别

| 条目 | 根因 | 信号可捕获性 |
|------|------|-------------|
| E051 | 内核未实现 syscall | 不可捕获，进程直接终止 |
| E164 | 编译期 adjtime 函数缺失 | 编译期 |
| E246 | 已实现但被 seccomp 拦截 | 可捕获，si_syscall 携带 syscall 号 |

## 根因分析

HarmonyOS 沙箱 seccomp 策略直接拦截部分 Linux 私有 syscall。该策略不可被应用层修改，
调用必然触发 SIGSYS 终止进程。

## 解决方案

### 推荐方案（graceful degradation）

检测 SIGSYS 后降级/跳过受限功能，或仅保留不触发受限 syscall 的功能子集：

```c
struct sigaction sa;
sa.sa_sigaction = on_sigsys;
sa.sa_flags = SA_SIGINFO;
sigaction(SIGSYS, &sa, NULL);
```

### smoke test 策略

使用不触发受限 syscall 的路径（如 `--version`），退出码 0。

## 验证命令

```bash
adjtimex --print                     # 预期: Signal 31 (core dumped)
adjtimex --version; echo $?          # 预期: 0（不触发受限 syscall）
```
