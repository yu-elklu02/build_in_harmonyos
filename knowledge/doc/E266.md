# E266 — lld 链接器缺少 libxml2.so.16 依赖导致 clang 链接失败

## 错误特征
编译时 clang 调用 lld 链接器，lld 是动态链接的 ELF 二进制，运行时需要 libxml2.so.16。
当系统库搜索路径中找不到 libxml2.so.16 时，lld 无法启动，输出以下错误：

```
Error loading shared library libxml2.so.16: (needed by .../llvm/bin/lld)
Error relocating .../llvm/bin/lld: xmlFreeDoc: symbol not found
...
clang-15: error: unable to execute command: No such file or directory
clang-15: error: linker command failed due to signal (use -v to see invocation)
make: *** [Makefile:6: all] Error 1
```

## 触发条件
- 构建系统: 任何使用 clang 的构建系统（make/cmake/autotools 等）
- 阶段: linking（链接阶段）
- 平台: HarmonyOS with ohos-sdk clang 15.0.4

## 根因分析
ohos-sdk 自带的 lld 链接器（位于 `/data/service/hnp/ohos-sdk.org/ohos-sdk_26.0.0.18/ohos/native/llvm/bin/lld`）
是动态链接的 ELF 二进制文件，其 NEEDED 依赖中包含 `libxml2.so.16`。
虽然系统中已安装 libxml2（位于 `/storage/Users/currentUser/usr/local/lib/libxml2.so.16`），
但 musl 动态链接器默认不搜索该路径，且 `LD_LIBRARY_PATH` 在某些情况下不生效，
导致 lld 加载失败，进而 clang 链接阶段失败。

## 解决方案

### 推荐方案
使用 `-fuse-ld=/data/service/hnp/bin/ld` 编译选项指定 GNU ld 2.45 作为链接器，
绕过有依赖问题的 lld。GNU ld 不依赖 libxml2，可以正常工作。

不同构建系统的注入方式不同：

**Makefile / Autotools / Meson** — 通过 `extra_ldflags` 或 LDFLAGS 传入：
```bash
# 在 LDFLAGS 中添加
LDFLAGS="-L$DEFAULT_PREFIX/lib -fuse-ld=/data/service/hnp/bin/ld"

# 或直接在编译命令中指定
clang -fuse-ld=/data/service/hnp/bin/ld -o output source.c $(CFLAGS) $(LDFLAGS)
```

**CMakeToolchain（conan 2.x）** — ⚠️ CMakeToolchain 没有 `extra_ldflags` 属性，
必须使用 `extra_exelinkflags` 和 `extra_sharedlinkflags` 分别注入：
```python
tc = CMakeToolchain(self)
tc.extra_exelinkflags.append("-fuse-ld=/data/service/hnp/bin/ld")
tc.extra_sharedlinkflags.append("-fuse-ld=/data/service/hnp/bin/ld")
tc.generate()
```
上述标志会写入 `CMAKE_EXE_LINKER_FLAGS_INIT` 和 `CMAKE_SHARED_LINKER_FLAGS_INIT`，
CMake try-compile 阶段也会继承，确保编译器检测不再失败。

> ❌ `tc.extra_ldflags.append(...)` 在 CMakeToolchain 上会报 `AttributeError`，
> 该属性仅存在于 AutotoolsToolchain / MesonToolchain。

### 回退方案
设置 `LD_LIBRARY_PATH` 包含 libxml2.so.16 所在目录（在某些环境下可能不生效）：
```bash
export LD_LIBRARY_PATH=/storage/Users/currentUser/usr/local/lib:$LD_LIBRARY_PATH
```

### 禁止做法
- ❌ 不要用 `ln -sf` 创建软链接到系统库路径（R5 铁律：HMDFS 软链接问题）
- ❌ 不要尝试修改 lld 二进制本身

## 验证
```bash
# 验证 lld 是否受影响
/data/service/hnp/ohos-sdk.org/ohos-sdk_26.0.0.18/ohos/native/llvm/bin/lld --version 2>&1 | grep -q "libxml2" && echo "AFFECTED" || echo "OK"

# 验证 GNU ld 可用
/data/service/hnp/bin/ld --version

# 验证使用 -fuse-ld 编译成功
clang -fuse-ld=/data/service/hnp/bin/ld -o /dev/null source.c
```
