# E215: Conan 打包时 SONAME 符号链接缺失

> **结构化数据**: [../graph/E274.kv](../graph/E274.kv)
> **严重度**: 🟡 medium | **分类**: packaging/runtime/linking | **自动修复**: ✅ create-soname-symlink

---

## 错误特征

```
Error loading shared library libxxx.so.X.Y: (needed by ./binary)
Error relocating ./binary: symbol_name: symbol not found
```

## 根因

Makefile 使用 `-Wl,-soname,libxxx.so.X.Y` 编译共享库，但 `conanfile.py` 的 `package()` 方法只复制了 `libxxx.so` 文件，未创建版本化 SONAME 符号链接 `libxxx.so.X.Y` → `libxxx.so`。运行时动态链接器解析 ELF 的 NEEDED 条目时找不到版本化 SONAME 文件，导致加载失败。

## 验证命令

```bash
# 检查共享库的 SONAME
llvm-readelf -d libxxx.so | grep SONAME

# 检查包中是否有 SONAME 符号链接
ls -la $PREFIX/lib/*.so*

# 检查二进制 NEEDED
llvm-readelf -d /path/to/binary | grep NEEDED
```

## 解决方案

### 方案1：创建 SONAME 符号链接（推荐）

在 `conanfile.py` 的 `package()` 方法中，复制 `libxxx.so` 后创建 SONAME 符号链接：

```python
def package(self):
    # ... 复制共享库 ...
    lib_dir = os.path.join(self.package_folder, "lib")
    copy(self, "build/libxxx.so", src=self.source_folder, dst=lib_dir, keep_path=False)
    # 创建 SONAME 符号链接（供运行时链接器解析 NEEDED 条目）
    soname_link = os.path.join(lib_dir, "libxxx.so.X.Y")
    if not os.path.exists(soname_link):
        os.symlink("libxxx.so", soname_link)
```

### 方案2：直接复制为版本化文件名

```python
copy(self, "build/libxxx.so", src=self.source_folder,
     dst=os.path.join(lib_dir, "libxxx.so.X.Y"), keep_path=False)
```
