# E280 — OHOS 静态构建下 Thread 静态包注册缺失导致核心 thread.test hang

PR: !3200 | Tcl 8.6.14 | 适配路径：路径 B（贡献创新）| 日期: 2026-08-01

## 错误特征

`unix/tests/thread.test` 在 OHOS aarch64 静态构建上 hang：

```
timeout 180 tcltest unix/tests/thread.test -testdir unix/tests
rc=124  日志 0 行  主线程 wchan=FUTEX  副线程 wchan=EVENTPOLL
```

最小复现（worker 线程内 `interp create` 子解释器）：

```
set i [interp create]
$i eval {package require -exact Thread 2.8.9}
→ can't find package Thread exactly 2.8.9
```

## 根因

1. **静态构建**（`TCL_SHLIB_EXT=""`，`load *.so` 不可用）：0010 将 Thread_Init
   静态链接进 tclsh/tcltest，仅在 AppInit 主解释器调用，**未注册
   `Tcl_StaticPackage(interp, "Thread", Thread_Init, NULL)`**（仅 sqlite3 注册）。
2. thread-7.16/7.17 在 worker 线程内创建子解释器并 require Thread → 失败 →
   worker 死亡 → 主线程 `vwait ::threadIdStarted` 永久等待 → hang。
3. **TCLLIBPATH=build-release/pkgs 前置 auto_path**：pkgs/thread2.8.9 的动态
   `load libthread2.8.9` 形式会覆盖静态桥接 → "dynamic loading is not currently
   available on this system"。

## 修复（补丁 0013–0015）

| 补丁 | 内容 | 作用 |
|---|---|---|
| 0013 | 新增 `library/pkgIndex.tcl`：`package ifneeded Thread 2.8.9 [list load {} Thread]` | 子解释器 require Thread 走静态加载 |
| 0014 | `unix/tclAppInit.c` OhosStaticPkgs_Init 增加 `Tcl_StaticPackage(interp, "Thread", Thread_Init, NULL)` | 注册静态包（镜像 sqlite3 方式） |
| 0015 | `pkgs/thread2.8.9/pkgIndex.tcl.in` Thread 行改 `load {}` 静态形式 | 防 TCLLIBPATH 动态覆盖 |

关联知识主题：

- **ThreadJoin 非 joinable/无效句柄保护**（0011/0012 相关）：
  thread-5.0/5.1/5.2（Joining threads / after the fact / detached）、
  Thread 包 thread-4.4/4.5（-joinable / join detached）、
  无效句柄组 thread-14.3/19.7/20.5/21.5/21.8 全部 0 failed。
- **ThreadReap 稳定快照**（0011 thread-test-reap-snapshot）：
  Thread 包套件 122 passed / 16 skipped / 0 failed。

## 适用边界

- 适用：Tcl 8.6.14 静态构建 + 需要子解释器 require Thread 的核心测试；
- 不适用：动态加载可用的常规构建（无需 0013–0015）；
- 知识库查重：关键词 ThreadJoin/ThreadReap/Tcl_StaticPackage/package require
  Thread/vwait/TCLLIBPATH 均无命中；"静态"命中条目（E005/E028/E073/E107 等）
  为其他库链接问题，与本主题无关 → 未覆盖，新建 E215。
