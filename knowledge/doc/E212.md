# E212: hmmac 安全标签阻止用户路径 .so 的 dlopen

## 基本信息
- **严重度**: 2
- **类别**: security|hmmac|platform_limitation
- **触发工具**: runtime|test|perl|python
- **阶段**: runtime

## 错误特征
```
Error loading shared library.*\.so.*Permission denied|Can't load.*\.so.*Permission denied|dlopen.*Permission denied
```

**关键词**: Permission denied, loading shared library, dlopen, hmmac, security label, hnp_file, hishell_hap_data_file, hmdfs, Perl XS, DynaLoader, ctypes CDLL

## 根因分析

OpenHarmony 的 hmmac (Harmony MAC) 安全模块根据文件所在路径分配安全标签：

| 路径 | 文件系统 | 安全标签 | dlopen |
|------|---------|---------|--------|
| /data/service/hnp/ | hmfs (inherit_parent) | hnp_file | ✅ 可加载 |
| /storage/Users/ | hmdfs | hmdfs | ❌ Permission denied |
| /data/storage/el2/base/ | hmfs | hishell_hap_data_file | ❌ Permission denied |

Perl/Python 进程运行在 `hnp_file` 安全上下文中（因为解释器二进制位于 /data/service/hnp/），hmmac 策略仅允许加载 `hnp_file` 标签的 .so 文件。

用户无权写入 /data/service/hnp/（属主 installs:installs），导致编译产物无法被 dlopen 加载。

**影响范围**: 所有需要 dlopen 加载 .so 的 Perl XS 模块、Python C 扩展、JNI 库等，当 .so 位于用户可写路径时。

## 验证
```bash
ls -Z <so_path>
# 若标签不是 u:object_r:hnp_file:s0，则 dlopen 会失败
```

## 推荐方案
- **方法**: install-to-hnp-path
- **描述**: 通过 hnp 包管理器或 cmd-pkgs 将 .so 安装到 /data/service/hnp/ 路径，获得 hnp_file 安全标签
- **命令**: 需通过系统包管理器安装，非用户可自行操作
- **自动修复**: false

## 回退方案
- **方法**: verify-elf-only
- **描述**: 无法安装到 hnp 路径时，仅做 ELF 技术验证（file/readelf/nm），记录平台限制，不阻塞编译流程
- **命令**: `file <so_path> && llvm-readelf -d <so_path> && llvm-nm -D <so_path>`

## 禁止做法
- ❌ `chmod 777` / `chmod a+rwx *.so` — 权限问题不是 Unix 文件权限导致，chmod 无法改变安全标签
- ❌ `chcon` / `setfattr security.hmmac` — 普通用户无权修改 hmmac 安全标签

## 与 E131 的区别

E131 是 LD 环境变量干扰 musl 动态链接器的 dlopen，通过 `env -u LD` 可解决。
E212 是 hmmac 安全标签限制，`env -u LD` 无效，需要将 .so 安装到正确路径。
在实际排障中应先检查 E131（env -u LD），排除后再检查 E212（ls -Z 标签）。
