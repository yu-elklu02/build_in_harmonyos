# E229: Standalone tests must link the internal libc fallback object

> Contributor: 1catmint1 | Status: DRAFT | Created: 2026-07-19

## Symptom

The library itself links on HarmonyOS, but an upstream standalone test fails:

```text
undefined reference to `explicit_bzero`
```

Skipping the test or linking a shared build does not establish that its tested
path is valid.

## Root cause

The target libc lacks an API that the project supplies internally. The fallback
is compiled into the main library and may have hidden visibility. A standalone
test target that links only common test objects does not automatically receive
that implementation, and a hidden symbol in the shared library cannot satisfy
an external reference.

## Fix

Trace the failing test's call path to the exact fallback object and add that
object to the test target's `LDADD`. For a release tarball workflow that does
not run `autoreconf`, update both the source `Makefile.am` and the shipped
`Makefile.in` through the normal patch pipeline.

```make
test_crypt_nested_call_LDADD = \
        lib/libcrypt_la-util-xbzero.lo $(COMMON_TEST_OBJECTS)
```

Keep the original test source, assertions, failure exit status, and declared
SKIP conditions unchanged. Do not make the internal fallback a new public ABI
solely for test linkage.

## Validation

On libxcrypt 4.5.2 with HarmonyOS libc, linking the exact xbzero fallback made
`crypt-nested-call` build and preserved the complete upstream test set. Fresh
static and shared Conan runs passed 54/54 and 52/52 selected entries
respectively, with zero skipped or unexpected terminal results.

## Related knowledge

- E213 covers implementing a generally missing libc function.
- E229 applies when the project already contains the implementation but a
  standalone test target omits its object or cannot access a hidden symbol.
