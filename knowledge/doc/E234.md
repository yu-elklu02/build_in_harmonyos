# E234 - 静态 Autotools 库的 Conan fPIC 映射与共享链接回归

## 现象

静态构建若收到 `--with-pic`，部分上游会在 `configure` 阶段明确拒绝；若为绕开该检查而关闭所有 PIC 标志，生成的静态归档又可能在整体链接进共享 ELF 时出现非 PIC 重定位错误。

## 根因

`--with-pic` 是 Libtool 配置项，Conan 的标准 `fPIC` 选项则由 `AutotoolsToolchain` 写入 `CFLAGS` 和 `CXXFLAGS`。二者不是同一个接口。项目可能禁止前者与纯静态模式组合，但仍允许静态对象使用编译器 `-fPIC`。

因此必须回读当前 Conan 版本的真实生成结果，区分“配置参数”和“编译标志”，不能凭参数名称推断映射关系。

## 修复

1. 配方保留标准 `shared` 与 `fPIC` 选项，默认 `fPIC=True`；Windows 删除 `fPIC`，shared 模式删除 `fPIC`。
2. static + `fPIC=True` 时，精确移除至多一个上游不接受的 `--with-pic`；重复项直接失败。
3. 在 `toolchain.generate()` 前确认 `toolchain.cflags` 中恰有一个 `-fPIC`，避免缺失或重复注入。
4. 不增加独立测试编号。将两个静态库用 `--whole-archive` 链入一个 `-shared -fPIC -Wl,-z,defs` 产物，作为既有制品工作流的内部检查。

## 验证

- `conanbuild.conf`：`--disable-shared` 与 `--enable-static` 各一次，且没有 `--with-pic`。
- toolchain 环境脚本：`CFLAGS` 中唯一 `-fPIC`。
- 输出 ELF：Machine 为 AArch64，Type 为 DYN。
- 动态段：没有被测库的 `NEEDED`，没有 `RPATH` 或 `RUNPATH`。
- OpenHarmony PC 目标端 fresh W3 r35：shared/static 两次 `conan create` 均返回 0；官方上游入口 `2/2`、consumer `11/11`，逻辑总数 `13/13`，失败、超时、未执行和未知终态均为 0。
- 证据校验终态：`ALSA_W3_R35_EVIDENCE=PASS upstream=2/2 consumer=11/11 modes=2`。
- 冻结输入、runner 与回收证据包 SHA256 分别为 `17dde268ec49738b2328000619068923d8c4f5659e531b26b056a9f4a78278ec`、`3409e512c1b3d8c8e5e3188373399264d986c14d601db4dafcab64594811d2d2`、`cfe65995eec2d3912c967cbf0036976f44bd8b4ddecca26d8481870c788e2e75`。
- 测试统计：该回归仍属于原制品工作流，shared/static 重跑不重复计数。

## 证据边界

目标端 r35 证明本配方在 shared/static 两种制品模式下完成构建并执行全部 13 个逻辑入口；它不等同于 W4、CI 或制品发布结果。
