# E293 — 2003 年代旧 C++ 代码在 C++17 下编译失败（dynamic-exception-spec / register）

## 错误特征

```
error: ISO C++17 does not allow dynamic exception specifications [-Wdynamic-exception-spec]
const char* ThesaurusImpl::next(int& id) throw(AiksaurusException)
error: ISO C++17 does not allow 'register' storage class specifier [-Wregister]
```

clang 以 `-std=c++17` 编译 2003 年前后编写的 C++ 代码时报 hard error。

## 触发条件

- 构建系统: autotools（configure + make）或 cmake
- 阶段: compilation（make/clang++）
- 环境: OHOS 编译 profile 设置 `compiler.cppstd=17`

## 根因分析

2003 年前后（C++98 时代）的代码广泛使用两种 C++17 已移除的语法：
1. **动态异常规范** `throw(Type)` —— C++17 移除，clang 默认 hard error
2. **register 存储说明符** —— C++17 移除

OHOS 标准编译 profile 固定 `compiler.cppstd=17`，clang `-std=c++17` 下
这些特性从 C++98 的合法语法变为编译错误。知识图谱引擎在此场景易误匹配：
- E001（cc not found）—— 实际 clang 存在
- E165（shebang 问题）—— 与 configure 无直接关系

## 解决方案

### 推荐方案（toolchain-flag）

在 conanfile.py `generate()` 中通过 Conan Toolchain 追加降级标志（R33）：
```python
tc.extra_cxxflags.append("-Wno-error=dynamic-exception-spec")
tc.extra_cxxflags.append("-Wno-error=register")
```
把两个诊断降级为 warning，代码可正常编译。这是对旧代码最轻量的处理，
无需改动大量源码（aiksaurus 涉及 60+ 处 throw(...)）。

### 回退方案（source-patch）

若项目传递 `-Werror` 导致降级无效，需 patch 源码：
- 删除全部 `register` 关键字
- 将 `throw(Type)` 替换为 `noexcept(false)`

### 禁止做法

- ❌ `--host=...ohos` / `--build=...` 绕过（误判交叉编译，AC_RUN_IFELSE 跳过）
- ❌ 把 `cppstd` 降到 11/14 掩盖问题（OHOS profile 固定 17，且降低标准不解决根因）

## 验证

```bash
clang++ -std=c++17 -Wno-error=dynamic-exception-spec -Wno-error=register -c src.cpp
# 应仅剩 warning，无 error
```
