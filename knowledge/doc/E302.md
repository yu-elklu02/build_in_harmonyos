# E302 - Verify `open_memstream` behavior, not only its symbol

## Error signature

```text
PosixMemstreamTest.CanCheckBufferWithContents
Expected: "Hello world
"
Actual:   ""
```

The CMake cache reports `HAVE_OPEN_MEMSTREAM=1`, but every captured `FILE*`
output comparison receives an empty buffer.

## Root cause

A symbol check proves only that `open_memstream` can be linked. It does not
prove the runtime contract used by callers: buffered writes must be published
and the cookie stream must close successfully.

The validated OpenHarmony libc creates the memory stream with an internal
descriptor of `-1`. Its current `fclose()` path rejects negative descriptors
with `EBADF` before calling `fflush()`. Short writes therefore remain buffered,
the memory-stream callback never publishes them, and callers observe an empty
string even though the symbol exists.

## Recommended solution

1. Prefer a target behavior probe that writes a string smaller than `BUFSIZ`,
   closes the stream, requires `fclose()` to return zero, and compares the
   published buffer.
2. When a cross configuration cannot run that probe, bind any override to
   target evidence or the exact libc implementation.
3. Disable `HAVE_OPEN_MEMSTREAM` only for the affected target and retain the
   project's existing fallback path.
4. Rerun every upstream test target that uses the capture wrapper; do not count
   configuration success as runtime verification.

For GROMACS 2026.3, the OHOS toolchain override selects its existing fallback
without changing production code. The fresh target run then passed
`TestUtilsUnitTests`, `UtilityUnitTests`, and `MdrunUtilityUnitTests`.

## Forbidden approaches

- Do not treat symbol presence as proof of the close and flush semantics.
- Do not insert only `fflush()` before the broken `fclose()`; that can expose
  the bytes while leaving the cookie stream registered and allocated.
- Do not change reference output to an empty string or skip the complete CTest
  target.

If output capture must remain available, use a normal writable file below
`TMPDIR`, read it back, and verify cleanup explicitly.

## Verification

```text
target behavior probe -> CMake capability value -> wrapper consumers ->
TestUtilsUnitTests + UtilityUnitTests + MdrunUtilityUnitTests
```

Record the exact target libc version and the full current PR revision with the
result. A host-only probe cannot validate the target capability.
