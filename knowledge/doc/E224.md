# E224：alternate signal stack 拥有者线程生命周期

## 知识类型
新增知识草稿，不预占正式 E 编号。

## 扩展目标/正式未命中证据
绑定基线检索 `sigaltstack`、`SS_DISABLE`、`signalStack`、owner thread，仅通用 libc 对比提到接口存在，未命中“注册、拥有者线程退出、注销、join 与 backing memory 回收顺序”的正式根因条目。

## 扩展原因与原条目差异
这是资源所有权与线程生命周期模式，不等同于“平台是否提供 sigaltstack”。正式 `knowledge/graph/E045.kv` 描述 W^X/RWX executable-memory 风险，是出现 VM/JIT 崩溃时必须用 RWX、RW→RX 和最小指令探针证伪的相似假因；E045 不是本 source event 的直接根因。

## 不直接修改正式知识声明
仅新增草稿，不修改正式 graph、doc、operations，不声称已经 promote。

## 绑定基线
`abc819ed421ffae696bdc9c88d2ec17ed685aaa4`。

## 通用问题
线程注册 alternate signal stack 后，线程状态与 backing memory 可能由不同对象或线程管理。若注销和释放的所有权不一致，退出路径可能稳定崩溃。

## 错误指纹
`SIGSEGV(SEGV_MAPERR)`、`je_arena_dalloc_small`、`free(signalStack)`、`sigaltstack(... SS_DISABLE ...)`。

## 根因模型
allocate → register → use → disable → thread exit/join → free 是需要审计的资源链。join 只证明线程结束，不自动证明注册资源已按实现要求注销；allocator 顶帧也不等于 allocator 缺陷。

## 适用范围
自行 malloc 或映射 alternate stack 的 runtime、VM、profiler 和多线程信号程序。

## 不可泛化边界
不得宣称所有 POSIX 平台都以相同方式崩溃，也不得断言所有实现要求相同回收时点；应以目标平台接口语义、返回值和真实负载为准。

## FAIL→修复→PASS
Poly/ML source event Round 3 稳定崩溃；FaultLogger、反汇编和重复复现定位到 signal-stack 释放轴。拥有者线程退出前执行 `SS_DISABLE` 且保留注册能力后，Round 9/16 形成初始 PASS，Round 16 日志 SHA-256 为 `d7663a2dcd5d1db1f87491844ef7c2cf12463218ffad1b233454c32318d377c6`。

官方 R8 修复进一步移除 `__OHOS__` 平台名门控，改为 `SA_ONSTACK && HAVE_SIGALTSTACK` 能力门控。该最终版本已通过完整设备 CI Round 17：原生 bootstrap 7阶段、上游273个 runner、静态 consumer、SML consumer 和 destructive negative test 均完成，日志无 SIGSEGV/exit 139。Round 17 日志 SHA-256：`a9f67da43f9b029c36e25fcf2489782dd6944e078f98af879d2c7b2436c39f03`。

## 禁止模式
禁止未确认注销成功就释放 backing memory；禁止仅凭平台宏整体禁用能力；禁止把 join 等同于资源已注销；禁止从单一 HarmonyOS 事件推导所有 POSIX 平台绝对规则；禁止未做 executable-memory 探针就直接套用 E045。

## 证据来源
`reports/segv-probe-report.md`、Round 3/9/16 历史报告、`reports/ci-round-17-pass.md`、Round 17 权威日志和适配补丁审查证据。

## Source event
Poly/ML 5.9.2 只作为在 OHOS 上发现的可重复 source event；Round 9/16 记录初始修复历史，Round 17 记录移除 `__OHOS__` 后的最终能力门控版本。正式条目应使用通用生命周期语言，并由 `SA_ONSTACK` 与 `HAVE_SIGALTSTACK` 能力探针门控注销建议，而非使用平台名宏。
