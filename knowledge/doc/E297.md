# E297 - 应用包运行时资源完整性检查

## 使用说明

当命令行工具、服务或桌面程序编译成功并能启动，但因缺少网页、配置模板、字典、插件清单等资源而降级或报错时，使用本条目建立运行时资源闭包。

## 适用范围

- 上游安装规则同时写入 `bin/` 与 `share/`、`etc/` 或插件目录。
- 源码中存在编译时资源路径常量。
- 配方绕过上游 `install`，手动复制可执行文件。

## 输入定义

- 上游安装规则和资源文件清单。
- 程序编译时使用的 prefix、资源根路径和默认配置路径。
- 功能测试所需的最小运行场景。

## 输出定义

- 保持上游相对布局的完整包目录。
- 可执行文件、资源、配置样例和许可证均存在。
- 在不依赖源码树和开发机文件的隔离目录中通过功能测试。

## 实现步骤

1. 从 `install` 规则和源码字符串提取资源路径。
2. 建立 `源文件 -> package_folder` 映射表。
3. 复制资源时保持相对布局和必要重命名。
4. 在隔离工作目录运行打包后的程序，覆盖实际资源读取路径。

## 示例

```python
www_dir = os.path.join(self.package_folder, "share", "app", "www")
copy(self, "app", src=self.source_folder,
     dst=os.path.join(self.package_folder, "bin"), keep_path=False)
copy(self, "localindex.html", src=self.source_folder,
     dst=www_dir, keep_path=False)
copy(self, "config.sample", src=self.source_folder,
     dst=os.path.join(self.package_folder, "share", "app"), keep_path=False)
```

测试输入是仅含安装包的目录；预期输出是程序能够读取资源并完成目标功能，而不是只返回 `--version`。

## 禁止做法

- 看到 `bin/app` 存在就判定打包完整。
- 测试时仍从源码目录读取资源。
- 修改程序将“资源缺失”错误静默降级，从而掩盖漏包。
- 把可生成的缓存、日志或用户数据误当成只读资源打包。

## 验证证据

PR #2106 `polipo` 在包内补齐默认网页和配置样例，并通过隔离运行检查；该方法同样适用于带模板、字典和插件元数据的应用。
