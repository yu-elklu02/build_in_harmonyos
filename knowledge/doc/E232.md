# E232: Prefix Conan Autotools configure with the native OHOS shell

> Contributor: 2301_80739235 | Status: DRAFT | Updated: 2026-07-29

## Symptom

A native OHOS `conan create` restores its dependencies and enters the package
build, but fails before configuration begins. The log shows Conan running the
archive's `configure` path directly, followed by `Permission denied`, error 126,
and a traceback from `autotools.configure()`.

The build profile may already define `CONFIG_SHELL`. That does not change the
first process in the command emitted by Conan's `Autotools.configure()` helper.

## Root cause

`Autotools.configure()` emits the source `configure` path as the command's first
process. `CONFIG_SHELL` is consumed only after Autoconf has started, so it cannot
prefix this initial process. A native OHOS source location that rejects direct
script execution therefore fails before Autoconf can read the environment.

This distinction is specific to the build executor. `settings.os == "OHOS"`
also holds during Windows or Linux cross builds, where `/system/bin/sh` does not
exist. The native path must consequently be selected with
`settings_build.os == "OHOS"`.

## Fix

For the native OHOS build executor only:

1. Create Conan's `Autotools` helper normally so its official configure
   arguments remain authoritative.
2. Invoke `/system/bin/sh`, the official source `configure` path, and
   `autotools._configure_args` in that order.
3. Keep every non-OHOS build executor on `autotools.configure()`, including
   cross builds whose target `settings.os` is OHOS.
4. Continue with `autotools.make()` so the generated build contract is
   unchanged.

Do not replace Conan's generated arguments with a hand-written subset. That can
drop the compiler, dependency, prefix, and toolchain settings supplied by the
profile.

## Scope boundary

E232 covers only Conan's initial configure launch. General source-script
execution and interpreter-path failures remain covered by E087 and E165.
HarmonyOS triplet recognition remains E007. Later Autoconf temporary-directory
permission failures remain E011/E129. These are separate diagnostics and must
not be bundled into this entry.

## Validation

The opusfile r13 log records the exact direct command, `Permission denied`, the
`autotools.configure()` frame, and exit 126. The corrected recipe is validated
with four static branches:

- native OHOS selects the explicit system-shell command;
- the command preserves the official source path and
  `autotools._configure_args`;
- Windows/Linux build executors retain `autotools.configure()`;
- target `settings.os` alone cannot select a target-only executable.

The current recipe then passed the matching official Buildbot job for its
pre-classification HEAD. The classification-only follow-up must obtain a new
