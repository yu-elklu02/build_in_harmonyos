# E255: 资源型数据包在 OHOS 上的 Conan 适配与验证通用方法

> **Contributor**: junshi_liu | **Status**: Verified | **Updated**: 2026-07-28
> **Severity**: 2 | **Category**: packaging / resource-data / validation-methodology

## 适用范围

OHOS 上所有纯资源/数据型包（无编译步骤）的 Conan 适配：
图标主题、字体包、文档/帮助包、配置模板等。

## 错误特征

```text
symbolic link loop|BadZipFile|Symlink loop|no_test_sources|
stub_test_method|commands.json missing|L0 quality gate failed
```

## 根因

OHOS Conan 流水线主要为编译型 C/C++ 库设计，其 L0/L1/L2/L4/L5 质量门禁对纯资源型数据包
不适用。资源型数据包无编译步骤、无 ELF 产物、源码包可能包含符号链接循环。

## 解决方案

### conanfile.py 关键点

1. `package_type = "unknown"` — 标记非库/非应用，避免触发 commands.json 门禁
2. `no_copy_source = True`
3. `settings = "os", "arch"` — 不需要 compiler/build_type
4. `build()` — 直接 pass（无编译步骤）
5. `package()` — 用 copy() 将资源目录树复制到 share/
6. `package_info()` — cpp_info 的 bindirs/libdirs/includedirs/libs 全部置空

### source() 处理符号链接循环

```python
with tarfile.open(archive_path, "r:gz", errorlevel=0) as tf:
    tf.extractall(path=extract_to, filter="data")
```

### test_package 验证焦点

- 资源描述文件存在性（index.theme、fonts.conf 等）
- 描述文件关键字段完整性
- 资源文件格式合法性（SVG/PNG/XML）
- 断链检测：使用 followlinks=False 的 os.walk

## 禁止做法

- 为资源包创建 commands.json 或虚假二进制测试源文件（违反 PR 原子性）
