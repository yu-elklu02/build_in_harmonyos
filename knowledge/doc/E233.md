# E233: Gate unsupported RDHUP early-close advertisement on HarmonyOS poll and epoll

> Contributor: 2301_80739235 | Status: DRAFT | Updated: 2026-08-01

## Symptom

An OHOS build succeeds, but the official POLL and EPOLL wrappers fail
`test-closed` and `simpleclose_*` paths. An initial exploratory build made
the POLL subset pass and incorrectly treated EPOLL as proven. A clean
official-archive rebuild of the exact recipe still failed POLL and EPOLL
wrappers. No compiler or linker error is present.

## Trigger

- The platform headers define `POLLRDHUP` and `EPOLLRDHUP`.
- The library derives or hard-codes early-close feature bits from those
  definitions.
- The target-native `poll()` and `epoll()` implementations do not emit the
  corresponding half-close event for the tested socket lifecycle.

The header constant is only an API surface. It is not sufficient evidence that
the kernel and libc path implement the event semantics expected by a backend.

## Root Cause

Libevent's poll backend sets `EARLY_CLOSE_IF_HAVE_RDHUP` when `POLLRDHUP` is
defined. Its epoll backend uses `EPOLLRDHUP` in the event mask but advertises
`EV_FEATURE_EARLY_CLOSE` unconditionally in the backend feature table.
HarmonyOS satisfies the compile-time conditions but not the runtime contract,
so callers select code paths that the backends cannot honor.

## Fix

Under an `__OHOS__` source guard, set both RDHUP constants and their derived
feature values to zero. Use the derived epoll feature value in
`epollops.features` instead of hard-coding `EV_FEATURE_EARLY_CLOSE`. This
removes both false capability advertisements without changing other
platforms.

The preferred upstream-general alternative is a target-native socketpair
half-close probe whose result gates the capability. Do not skip the failing
tests, modify their expected results, or infer runtime behavior solely from a
header definition.

## Current Validation

- All six patches replay against the official archive through Git on
  LF-normalized inputs and Conan's `patch-ng` backend with `fuzz=False`; the
  resulting 221-file source trees are byte-identical.
- Target-semantic post-images are LF-only and hash-bound.
- The exact pre-fix index candidate failed the affected upstream wrappers.
- The capability fixes passed the official upstream CTest suite `49/49`.
- A clean `conan create` of the fully declared recipe completed successfully;
  package creation and the installed-package consumers passed.

## Scope Boundary

This entry records capability-detection mismatches on the tested runtime, not a
claim that every HarmonyOS release lacks every RDHUP behavior. Revalidate
`poll` and `epoll` independently on the exact target runtime before removing
either guard or generalizing the result to another backend.
