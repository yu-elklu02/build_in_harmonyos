# E289 — HELP2MAN=true 未生成手册页但 Automake 仍尝试安装

## 错误特征

交叉构建为避免执行不可用的文档生成器，将 `HELP2MAN` 设置为 `true` 或
`/bin/true`。构建阶段看似成功，但 `make install` 仍尝试复制不存在的手册页：

```text
PATH=.:$PATH pkgdatadir=. /bin/true ... -o grub-mkimage.1 grub-mkimage
/usr/bin/install -c -m 644 '.../grub-mkimage.1' '.../share/man/man1/grub-mkimage.1'
/usr/bin/install: cannot stat '.../grub-mkimage.1': No such file or directory
make[3]: *** [Makefile:11517: install-man1] Error 1
```

## 触发条件

- 构建系统：Autotools/Automake。
- 阶段：`make install`。
- 项目通过 `help2man` 等工具生成 `man_MANS` 中列出的手册页。
- 交叉构建使用 `HELP2MAN=true` 或等价空操作替代真实生成器。

## 根因分析

`HELP2MAN` 和 `man_MANS` 控制的是两个不同层面。前者是生成手册页时调用的程序；
把它替换成 `true` 只会让生成规则返回成功，不会创建输出文件。后者是 Automake
生成的安装清单，不会因为生成器被替换而自动清空。于是安装规则仍读取
`man_MANS`，并在复制不存在的 `.1`、`.8` 等文件时失败。

## 解决方案

### 推荐方案

若本次构建明确不打包生成的手册页，在同一次安装命令中覆盖 Automake 变量：

```bash
make install DESTDIR="$DESTDIR" man_MANS=
```

`man_MANS=` 必须传给 `make install`，仅在 configure/build 环境设置
`HELP2MAN=true` 不足以关闭安装规则。若上游提供正式的
`--disable-manpages`/`--disable-doc` 选项，应优先使用上游接口。

### 回退方案

当构建环境可以运行待分析的程序且 `help2man` 可用时，保留原 `man_MANS`，使用
真实生成器创建并安装有效手册页。

### 禁止做法

- 不得只设置 `HELP2MAN=true` 就假定文档安装已禁用。
- 不得用 `touch` 或空重定向伪造手册页。
- 不得用 `|| true`、`make -k install` 等方式忽略安装失败。

## 验证

先确认未覆盖 `man_MANS` 的安装会稳定命中缺失文件，再使用修复命令完成安装，
并检查代表性制品存在：

```bash
make install DESTDIR="$DESTDIR" man_MANS=
test -d "$DESTDIR/bin" -o -d "$DESTDIR/usr/bin"
```

`x86_64-elf-grub/2.12` 的验证证据：

- `linux-install.log`（SHA-256
  `7f10b0fd016e7aeffabc127eb15f1cd00ebe805d44da044604310ed1dc1ac65c`）记录
  `grub-mkimage.1` 缺失并以 `install-man1` 错误结束。
- `linux-install-no-man.log`（SHA-256
  `7b4319d14b658c53df5eb98abf2c1644b906da383b94bd9a1943af9d2482cb6e`）记录
  追加 `man_MANS=` 后完整走完安装目录。
- 强制 Conan 源码构建日志（SHA-256
  `0795adc153e041eb393451c82c4e53dab8d2a49c9fb8c403d36597bcf3eb2558`）记录
  配方实际执行带 `man_MANS=` 的安装命令，随后创建主包并通过消费者测试。
