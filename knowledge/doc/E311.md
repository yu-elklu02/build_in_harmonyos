# E311 - Verify Conan source-folder isolation before diagnosing mutation

## Symptom

A review reports that `replace_in_file(self.source_folder, ...)` in `build()`
must contaminate every shared/static package ID because it supposedly edits
one shared Conan source cache. The actual `conan create` log, however, says:

```text
Copying sources to build folder
Building your package in .../p/b/<package-build>/b
```

Both option variants can then complete from distinct package build paths.

## Root Cause

In Conan 2, `self.source_folder` is a contextual path, not always the recipe's
canonical cache source directory. With the default `no_copy_source=False`,
Conan copies sources into the package build area and points the build step at
that copy. Two package IDs therefore do not mutate each other's build source
merely because the recipe uses `self.source_folder`.

The risk is real under different contracts. A recipe with
`no_copy_source=True`, an editable workflow, or custom layout/path handling
may expose a shared or user-managed source tree. The runtime path and copy
policy must be established before classifying the edit.

## Decision And Fix

1. Inspect the create log for `Copying sources to build folder`.
2. Record the resolved source and build paths for each package ID.
3. Build at least two option variants and verify their selected artifacts.
4. Hash the canonical cache source before and after when contamination is in
   question.

If explicit isolation is still useful for readability or for future workflow
changes, create a resettable nested copy below `build_folder`:

```python
build_source = os.path.join(self.build_folder, "_source")
rmdir(self, build_source)
copy(self, "*", src=self.source_folder, dst=build_source)

replace_in_file(
    self,
    os.path.join(build_source, "CMakeLists.txt"),
    "add_library(foo SHARED ${LIBSRC})",
    "add_library(foo ${LIBSRC})",
)

cmake = CMake(self)
cmake.configure(build_script_folder=build_source)
```

This explicit copy is a defensive invariant, not proof that Conan's default
source handling was defective. Universally applicable source changes should
remain exported patches in `source()`.

## Verification

For iir1 1.10.0, the pre-fix logs already showed Conan's default per-package
source copy, so the AI contamination finding was a false positive. The recipe
was nevertheless made explicit and rerun on HarmonyOS PC in one new Conan
home: shared and static each passed 8 upstream plus 46 consumer commands, each
packaged only its selected library type, and the canonical source
`CMakeLists.txt` remained byte-identical to the official source after both
builds. Repeated shared/static executions are artifact contracts, not new
logical test cases.
