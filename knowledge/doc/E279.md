# E279 - 跨补丁引擎的上下文锚定补丁

## 使用说明

当本地 GNU `patch` 成功、CI 的 Conan `patch-ng` 也返回成功，但补丁后的脚本语法或语义错误时使用本条目。它解决的是补丁定位的通用问题，不限定具体库。

## 适用范围

- 发布包包含旧版 `config.guess`、`config.sub`、`configure` 等生成脚本。
- 本地与 CI 使用不同补丁引擎。
- 补丁包含 `@@ -N,0 +N,M @@` 这类没有未修改上下文的插入块。

## 输入定义

- 干净上游源码目录。
- unified diff 补丁。
- CI 使用的 `patch-ng` 版本及本地 GNU patch 版本。
- 修改后应满足的结构不变量，例如新增分支必须处于外层 `case`。

## 输出定义

- 带前后稳定上下文的补丁。
- GNU patch 和 patch-ng 均无 fuzz 应用成功。
- 修改后文件通过语法检查，目标分支位于预期语法层级。

## 根因

零上下文 hunk 只提供行号。文件中若存在多个相似位置，不同引擎可能选择不同插入点；“补丁返回成功”不等于修改后的语法结构正确。

## 解决步骤

1. 找到修改点前后各一段稳定且唯一的原文。
2. 重新生成包含双向上下文的 hunk。
3. 分别用 GNU patch `--fuzz=0` 和 `patch-ng` `fuzz=false` 应用到两份干净源码。
4. 对脚本执行语法检查和结构断言，再执行完整构建。

## 示例

```diff
@@ -143,2 +143,5 @@
 case "${UNAME_MACHINE}:${UNAME_SYSTEM}:${UNAME_RELEASE}:${UNAME_VERSION}" in
+    *:HarmonyOS:*:*)
+        echo aarch64-unknown-linux-ohos
+        exit ;;
     *:NetBSD:*:*)
```

```bash
patch --batch --fuzz=0 -p1 < fix.patch
sh -n config/config.guess
```

Python 验证 CI 同版本引擎：

```python
import patch_ng

patch = patch_ng.fromfile("fix.patch")
assert patch.apply(strip=1, root="clean-source", fuzz=False)
```

## 禁止做法

- 只检查补丁命令退出码，不检查修改后的结构。
- 用行号调整或开启 fuzz 掩盖定位不唯一。
- 用 `--build`/`--host` 绕过已经被错误插入的平台检测逻辑。

## 验证证据

PR #2103 和 #2104 的 HarmonyOS 平台分支均通过 GNU patch、patch-ng、脚本结构检查和完整 CI。
