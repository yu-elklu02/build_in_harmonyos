# E245: OHOS libc 未导出 vhangup（声明缺失+符号缺失），但内核 syscall 存在

> **Contributor**: junshi_liu | **Status**: Verified | **Updated**: 2026-08-05
> **Severity**: 3 (blocking) | **Category**: api-missing / platform-limitation / system-interface

## 原始失败与最小复现

```text
$ clang repro-vhangup.c -o repro-vhangup
warning: call to undeclared function 'vhangup'
ld.lld: error: undefined symbol: vhangup
```

## 根因分层

1. **声明缺失**：sysroot 头文件均无 vhangup 声明 → 编译期 implicit-function-declaration 警告。
2. **libc 符号缺失**：`nm -D libc.so | grep vhangup` 无输出（0 导出）→ 链接失败。
3. **内核 syscall 存在**：`__NR_vhangup 58` / `SYS_vhangup 58` → 内核能力存在但 libc 未封装，可 `syscall(SYS_vhangup)` 直调。

## 修复方案

仅 OHOS 条件下使用 syscall 封装（shim），不伪造 libc API：

```c
int vhangup(void)
{
    return (int)syscall(SYS_vhangup);
}
```

实现位于 `archives/a/agetty/2.42.2/src/ohos-utmpx-shim.c`。仅 OHOS 条件启用，非 OHOS 保持上游语义。

## 诊断流程

1. 最小复现：编译调用 vhangup() 的最小程序，观察声明警告与链接失败
2. 核验 syscall 编号：`grep SYS_vhangup $SYSROOT/.../bits/syscall.h`
3. 核验 libc 导出：`nm -D $SYSROOT/.../libc.so | grep vhangup`
4. 仅当"无声明 + 无导出 + 内核 syscall 存在"时，才启用 syscall shim
