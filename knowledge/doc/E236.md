# E236: Isolate non-relocatable Libtool dependency metadata

> **Contributor**: 2301_79503900 | **Status**: Verified | **Updated**: 2026-07-31
> **Severity**: 2 | **Category**: autotools / libtool / conan / static-linking

## Usage

Use this pattern when an Autotools project links a Conan dependency through
Libtool and either reports that a dependency `.la` file was moved or produces
a static archive that contains another complete `.a` file as a member.

## Symptom

```text
libtool: warning: library '.../libpcre2-8.la' was moved
libtool: error: '//lib/libpcre2-8.la' is not a valid libtool archive
```

Or after replacing with absolute `.a`:

```text
archive member 'libsqlite3.a' is neither ET_REL nor LLVM bitcode
undefined symbol: sqlite3_open
```

## Root Cause

Libtool treats visible `.la` files as authoritative metadata. Conan relocation
does not rewrite arbitrary paths stored inside those files. An absolute `.a`
value passed through `LIBADD` can cause `llvm-ar` to store the complete
dependency archive as one non-ELF member.

## Fix

1. Create a build-private directory with no `.la` files.
2. Copy only required static dependency archives into it.
3. Pass via scoped variables: `PCRE2_LIBS='-L<dir> -lpcre2-8'`
4. Remove generated `.la` metadata from the final package.

## Forbidden Approaches

- Do not delete or rewrite `.la` files inside a shared Conan package cache.
- Do not pass an absolute dependency `.a` through `LIBADD` without auditing.
- Do not move all flags into global `LIBS`.

## Verification

1. Clean Conan home and build folder.
2. All enabled upstream tests pass on target.
3. `llvm-ar t` on target archive shows object members, not nested archives.
4. Final package contains zero unintended `.la` files.
