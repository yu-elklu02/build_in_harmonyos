# E287 — AFL/fuzz corpus 替代测试框架

## 问题

部分 C/C++ 命令行工具（如 nmrpflash）上游提供 AFL 模糊测试入口（`fuzz.c` + `fuzz.bash` + `fuzzin/` 语料），但原样运行依赖 AFL/tmux/sudo/Linux sysfs/CAP_NET_RAW/TFTP 网络交互环境，这些在 OHOS 交叉编译 CI 中无法满足。

## 上游测试入口核验

对 nmrpflash 0.9.27 上游源码的核验结果：

| 入口 | 是否存在 | 能否在 OHOS CI 原样运行 |
|------|---------|----------------------|
| `Makefile` | ✅ | 可以，已用于编译 |
| `CMakeLists.txt` | ✅ | 可以，但未使用 |
| `fuzz.bash` | ✅ | ❌ 依赖 AFL/tmux/sudo/sysfs |
| `fuzz.c` | ✅ | 可以编译（无 AFL 依赖），但运行时需 CAP_NET_RAW |
| `mkfuzz.c` | ✅ | 可编译，生成 TFTP 语料 |
| `fuzzin/` 语料 | ✅ | 可作为确定性 runner 输入 |
| `t_tftp.c` | ✅ | ❌ 依赖 TFTP 网络服务 |
| `test/` or `tests/` dir | ❌ | — |
| `make check`/`ctest` | ❌ | — |

## 原样不可运行原因

1. **AFL**（afl-clang-fast）不在 OHOS 工具链中，`fuzz.bash` 使用 `afl-fuzz` 命令不可用
2. **tmux** 终端复用器不在 OHOS 环境中，`fuzz.bash` 用 tmux 管理并行 fuzz 会话
3. **sudo** 鸿蒙 sudo 为自研简化版，无 raw socket 权限授予能力
4. **sysfs**（`/proc/sys/kernel/core_pattern`）在 OHOS 只读文件系统中不可写
5. **CAP_NET_RAW** 未授予，`pcap_open_live()` 失败，`ethsock_create()` 无法创建 raw socket
6. **TFTP 网络服务** 无法在 CI 中部署，`tftp_put()` 超时退出
7. **/tmp 只读**（erofs），AFL 需要可写临时目录

## 替代方案：确定性 corpus runner

### 原理

`fuzz.c` 本身无 AFL 依赖（仅需标准 C 库和 `nmrpd.h`），AFL 依赖仅在 Makefile 的 `fuzz` target 中（使用 `afl-clang-fast`）。替换 AFL 编译器为标准 CC 即可编译为确定性 runner。

### 编译命令

```bash
# 使用项目同一编译器
CC=clang
CFLAGS="-I$SRC -I$LIBNL_INC -I$LIBPCAP_INC -D_DEFAULT_SOURCE -D_GNU_SOURCE"
LDFLAGS="-L$LIBNL_DIR -L$LIBPCAP_DIR -lnl-route-3 -lnl-3 -lpcap"

# 编译对象文件
$CC -c $CFLAGS $SRC/tftp.c
$CC -c $CFLAGS $SRC/util.c
$CC -c $CFLAGS $SRC/nmrp.c
$CC -c $CFLAGS $SRC/ethsock.c
$CC -c $CFLAGS $SRC/fuzz.c

# 链接
$CC fuzz.o tftp.o util.o nmrp.o ethsock.o -o fuzz $LDFLAGS
```

### 运行命令

```bash
# NMRP 模式（使用 fuzzin/ 语料）
./fuzz nmrp

# TFTP 模式（传递 corpus 文件）
./fuzz tftp fuzzin/tftp.bin
./fuzz tftp fuzzin/tftp/fsize_4096_blksize_1k.bin
./fuzz tftp fuzzin/tftp/fsize_4096_default.bin
```

### 语料统计

| 类型 | 数量 | 文件 |
|------|------|------|
| NMRP .pkts | 5 | `badorder1.pkts`, `badorder2.pkts`, `badorder3.pkts`, `badorder4.pkts`, `normal.pkts` |
| TFTP .bin | 3 | `tftp.bin`, `fsize_4096_blksize_1k.bin`, `fsize_4096_default.bin` |
| **总计** | **8** | |

### 验证结果

| 语料 | 退出码 | 说明 |
|------|--------|------|
| badorder1.pkts | 1 | `pcap_activate: no CAP_NET_RAW` (graceful) |
| badorder2.pkts | 1 | 同上 |
| badorder3.pkts | 1 | 同上 |
| badorder4.pkts | 1 | 同上 |
| normal.pkts | 1 | 同上 |
| fsize_4096_blksize_1k.bin | 255 | `Timeout while waiting for ACK(0)/OACK` (graceful) |
| fsize_4096_default.bin | 255 | 同上 |
| tftp.bin | 255 | 同上 |

**结果口径**：8/8 无崩溃（graceful handling）
- NMRP 退出码 1 为预期环境限制（no CAP_NET_RAW）
- TFTP 退出码 255 为预期环境限制（no TFTP server/timeout）
- **这不是上游原样测试通过率，不能替代真实网络服务测试**

## 适用范围

带 AFL fuzz 入口、fuzz corpus、网络交互测试、原始 socket 操作但 OHOS CI 无法原样运行的 C/C++ 命令行库。

### 已知适用
- **nmrpflash 0.9.27**（已验证，fuzz.c + fuzzin/ 语料，8/8 无崩溃）

### 潜在适用
- 其他带 `fuzz.c`/`fuzz.bash`/`fuzzin/` 的 AFL 入口项目
- 带 `raw socket`/`pcap`/`CAP_NET_RAW` 依赖的网络工具
- 带 `TFTP`/`NMRP` 等网络协议交互的测试程序

## 限制

1. 这不是上游原样测试通过率，不能替代真实网络服务测试
2. NMRP 模式仍需要 CAP_NET_RAW 才能完全运行协议解析逻辑
3. TFTP 模式需要 TFTP 服务才能验证传输逻辑
4. 当前仅验证了无崩溃（graceful handling），未验证协议解析正确性
5. 编译依赖 libnl/libpcap，需确保 Conan 远端可用

## 验证环境

- OHOS aarch64 交叉编译
- Clang 15.0.4
- libnl 3.7.0（Conan cache）
- libpcap 1.10.6（Conan cache）
