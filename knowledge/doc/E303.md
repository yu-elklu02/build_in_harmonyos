# E303 — 受限进程不可枚举根目录导致 hostfs 身份探测误判

## 错误特征

受限进程可以读取已知文件，却在把根目录枚举当作文件系统身份探测时提前失败。
GRUB 的 HarmonyOS PC 消费者测试在有效 Multiboot 对象已经生成后输出：

```text
[assert 1/10] assembled Multiboot object is non-empty
error: can't open `/': Permission denied.
ConanException: Error 7 while executing
```

## 触发条件

- 环境：容器、沙箱或应用安全域等允许搜索已知路径、但禁止枚举根目录的受限运行域。
- 阶段：宿主工具运行或 `test_package`。
- 程序对 `/` 调用 `opendir()` 只是为了确认伪文件系统或能力，不是为了读取目标文件。
- 实际文件访问由后续独立路径继续校验。

## 根因分析

目录搜索和目录项读取可以被分开授权。HarmonyOS PC 实机 SSH 域验证为：

```text
ROOT_SEARCH=yes
ROOT_READ=no
ROOT_LIST=no
KNOWN_FILE_READ=yes
```

因此，进程可以沿 `/system/bin/sh` 等已知路径访问文件，但不能枚举 `/`。GRUB
`hostfs` 在识别 host 伪磁盘时调用 `grub_util_fd_opendir("/")`；原实现把该
`EACCES` 转成 `GRUB_ERR_BAD_FILENAME`，使真实的 Multiboot 输入尚未由
`grub_hostfs_open()` 检查就提前退出。这不是输入文件损坏，也不是普通文件权限问题。

## 解决方案

### 推荐方案

在源码调用点做最小、能力驱动的降级：仅当以下两个条件同时成立时，让身份探测继续。

1. `errno == EACCES`。
2. 探测路径严格等于 `/`。

后续实际文件打开仍走原有 `grub_hostfs_open()`，所有其他路径和错误码保持原行为。
该条件直接描述失败能力，不依赖 `__OHOS__` 等平台宏，因此同样适用于出现相同权限
模型的容器或沙箱。本软件通过 `0010-grub-core-kern-emu-hostfs.c.patch` 固化该逻辑。

### 回退方案

若工具接口允许显式指定模块或数据目录，传入应用域可枚举的包目录，避免把 `/`
作为身份探测路径。没有此接口时应使用上述严格运行时条件补丁，不能改变系统根目录权限。

### 禁止做法

- 不得无条件吞掉所有 `opendir()` 错误；`ENOENT`、`ENOTDIR` 和其他权限故障必须保留。
- 不得对 `/` 执行 `chmod`/`chown`，也不得要求 root 或关闭应用沙箱。
- 不得把消费者命令包装为 `|| true`；必须验证有效输入成功、无效输入仍被拒绝。
