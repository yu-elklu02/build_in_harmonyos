# E223：HMDFS secure tmp 的 owner、mode、MAC 与真实写入闭环

## 知识类型
现有知识扩展草稿。

## 扩展目标/正式未命中证据

### 检索范围与筛选标准

本轮不是声称对整个知识库做无边界“完整检索”，而是对绑定基线 `abc819ed421ffae696bdc9c88d2ec17ed685aaa4` 的正式 `knowledge/graph/E*.kv` 与 `knowledge/doc/E*.md` 检索 `umask 022|chmod 777|chmod a+rwx|subs1.awk|config.status|HMDFS`，再按以下标准筛选：

1. 错误签名是否直接包含 `config.status`、`confXXXXXX`、`subs1.awk` 与 `Permission denied`；
2. 推荐方案是否涉及放宽 umask/DAC、固定临时目录、路径迁移、VPATH 或预编译替代；
3. 是否讨论 secure temporary directory 的 owner、mode、MAC、真实 IO 和下游工具访问；
4. 是同一错误模式的重复条目，还是只有关键词/平台表面相似。

### 主要扩展目标

- `knowledge/graph/E129.kv`、`knowledge/doc/E129.md`：直接同签名，且推荐将 `umask 077` 改为 `022`。本稿的核心新增价值是把判断标准从“目录似乎可写”提升为 **owner + mode + MAC label + create/write/read/remove IO + `config.status`/awk downstream access** 的联合证据，并将宽权限建议标为不可作 secure tmp 通用解。

### 需安全协调的条目

- E011：直接同类错误，推荐 `umask 022/000` 并对特定场景作安全判断；需与 E129 一并修订安全边界。
- E118：直接同类错误，明确给出 `chmod 777`，与本稿禁止模式正面冲突，应优先纠正。
- E136：直接同类错误，将 TMPDIR 与 `umask 022` 组合为通用修复；需要补充 private cache 和 MAC/owner 验证。
- E206：直接同类错误，同样推荐 `umask 022`，且命令文本存在拼写异常；应与 E129/E011 去重协调。

### 路径迁移/VPATH 相邻条目

- E052：同签名，但建议把 config.status 指向固定 `$HOME/tmp` 目录；路径迁移方向可能有效，仍缺 owner/mode/MAC/downstream access 证明。
- E060：同签名，建议复制源码到所谓 tmpfs 构建；属于迁移构建根策略，需先证明目标路径确为隔离且满足安全能力。
- E125：同签名，建议迁移到非 HMDFS 或 tmpfs；是平台规避/VPATH 相邻策略，不应把候选路径名本身当能力证明。
- E110：alternate build directory/VPATH 方向相容，没有宽权限推荐，但缺联合安全验证。
- E175：autoreconf、mktemp wrapper 或 VPATH，偏生成流程与路径迁移；仍需验证 wrapper 目标的安全属性。

### 直接同签名重复簇

- E112 与 E114：错误签名、根因、`bypass-mktemp`、固定临时目录和 copy-to-tmpfs fallback 高度重合，属于高重复条目；E114 与 E112 尤其应在官方策展时合并或明确差异，而不是继续并行扩散。
- E167：同样匹配 `config.status`/`subs1.awk`，以固定目录替换 `ac_tmp`；与 E112/E114 的固定目录方案构成重复簇，但根因描述更不确定。

### 仅表面相似或不作为本稿推荐依据

- E126：错误签名相同，但主要建议使用预编译包或改用 CMake，并断言 HMDFS 上 autotools 必定失败。它可作为“放弃现场构建”的平台限制记录，但不解释 secure tmp 的联合安全能力，也不应作为本稿修复建议依据。

KV 的 `similar_to` 保持为已存在且与当前模式语义最接近的 E206、E110、E112、E118、E175，不为覆盖清单而机械加入所有同签名 ID。条目优先级、冲突与重复簇分类保留在本 MD，避免 relation 退化为无语义的检索结果列表。
## 扩展原因与原条目差异
现有正式知识形成多个直接同签名条目和重复簇，但多数只在放宽 DAC、固定目录、路径迁移或放弃构建之间选择。新证据表明 `chmod 0700` 后仍失败，HMDFS mode 表象不足以证明安全语义；本稿不可替代的新增价值是联合验证 owner、mode、MAC、真实 IO 以及 `config.status`/awk 的 downstream access。

## 不直接修改正式知识声明
本提交不修改 E129 或相关正式条目，仅提供审核草稿。

## 绑定基线
`abc819ed421ffae696bdc9c88d2ec17ed685aaa4`。

## 通用问题
普通临时文件只需可写并清理；Autoconf 配置片段等敏感数据还要求隔离。路径存在、`test -w`、mkdir 成功、chmod 成功均不是完整证明。

## 错误指纹
`config.status: ... subs1.awk: Permission denied`、HMDFS directory mode 2771、`Read-only file system (EROFS)`。

## 根因模型
安全临时根是多维能力：当前进程 owner、目录/文件权限、MAC 标签、创建写入读取删除和下游工具访问必须同时成立。HMDFS 显示 mode 与传统 POSIX 预期可能不一致。

## 适用范围
Autotools/config.status、生成密钥或配置片段的工具，以及要求 private temporary directory 的构建步骤。

## 不可泛化边界
特定 app-private cache 路径不能作为跨应用固定常量；不同身份、用户、设备版本和 MAC 域必须重新探测或由 launcher 注入。

## FAIL→修复→PASS
Poly/ML Round 4 暴露只读 `/tmp`；Round 8 在 HMDFS 上即使保留 `umask 077` 并 `chmod 0700` 仍失败。改用经 owner/mode/MAC/IO 验证的应用私有缓存后 Round 12/16 PASS。日志 SHA-256：`d7663a2dcd5d1db1f87491844ef7c2cf12463218ffad1b233454c32318d377c6`。

## 禁止模式
禁止 `chmod 777`、`chmod a+rwx` 或放宽 umask 作为 secure tmp 通用解；禁止只凭 mode 数字宣布安全；禁止把固定 app-private 路径泛化；禁止静默 fallback 到未经隔离验证的路径。

## 证据来源
Round 4/8/12/16 报告、private cache preflight、最终日志和绑定基线 E129 等正式条目。
