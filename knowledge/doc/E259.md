# E259: Conan Release 的 -DNDEBUG 让 assert(含副作用的表达式) 整体不求值，触发上游 latent bug

> **Contributor**: GoliWie | **Status**: Verified | **Updated**: 2026-08-06
> **Severity**: 2 | **Category**: build-system / testing / ndebug / assert / conan-release

## 错误特征

```text
assertion self != NULL failed
FAIL: 256 out of 474 tests failed
```

## 根因分析

上游代码用 `assert(EXPR)` 包裹了一个有副作用的表达式（如
`assert(g_module_symbol(h, "sym", (gpointer*)&p))`），本意是"断言成功的同时完成取符号赋值"。
但 Conan 的 AutotoolsToolchain 在 build_type=Release 时注入 -DNDEBUG，C/C++ 标准下
`assert(EXPR)` 展开为 `((void)0)`，EXPR 根本不求值——于是赋值/调用从未发生，p 保持未初始化，
后续逻辑静默走错分支。

这类 bug 在上游裸 make check（无 NDEBUG）下永远不会触发，故属 latent bug。

## 解决方案

### 推荐方案：把副作用从 assert 中提出

```c
gboolean ok = g_module_symbol(h, "set_configure", (gpointer*)&sc);
assert(ok);
```

这样 NDEBUG 下断言虽被去除，但副作用（赋值/调用）仍执行。

### 回退方案

仅在 recipe 的测试编译阶段去掉 -DNDEBUG（如传 -UNDEBUG），但改变了 Release 构建的测试语义。

## 禁止做法

- 不要跳过或空壳化失败的测试
- 不要在生产源码里全局取消 NDEBUG

## 验证

```bash
grep -n DNDEBUG build-release/tests/Makefile  # 确认含 -DNDEBUG
```

enchant 2.8.2 round-24 起 474/474 全 PASS。
