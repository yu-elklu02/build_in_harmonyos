# E248: patch 致 Makefile.in mtime 早于 Makefile.am，无 automake 时触发重生成崩溃

> **Contributor**: GoliWie | **Status**: Verified | **Updated**: 2026-08-06
> **Severity**: 2 | **Category**: autotools / build-system / patch / timestamp

## 错误特征

```
automake-1.16: command not found
Makefile:*** Makefile.in] Error 127
```

## 根因

当 Conan 的 `apply_conandata_patches` 按 patch 文件内 hunk 顺序应用时，若 Makefile.am
的 hunk 排在 Makefile.in 之后，应用后 Makefile.am 的 mtime 会晚于 Makefile.in。GNU make
的标准依赖规则 `Makefile.in: Makefile.am` 据此判定 Makefile.in 过期，调用 `build-aux/missing
automake-1.16` 重生成；而鸿蒙 PC 仅有 autoconf 系列而无 automake/aclocal，重生成以 exit 127
失败。

## 推荐方案

在 `conanfile.py` 的 `build()` 方法中，`apply_conandata_patches(self)` 之后立即用 `os.utime`
把 Makefile.in 的 mtime 对齐到 Makefile.am：

```python
os.utime(makefile_in, ns=(os.stat(makefile_am).st_mtime_ns,)*2)
```

零新增依赖、不碰源码逻辑、不跑 autoreconf。

## 禁止做法

- 不要安装 automake 扩大依赖面
- 不要在无 automake 的设备上跑 `autoreconf --force`

## 验证

```bash
ls /data/service/hnp/bin/ | grep -E "automake|aclocal"  # 确认无输出
stat -c "%Y %n" tests/Makefile.am tests/Makefile.in     # 确认 .in mtime >= .am
```
