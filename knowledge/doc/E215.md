# E215: LuaRocks 3.13.0 targeting Lua 5.5 needs Path B test-dependency handling

> **Contributor**: m0_46382645 | **Status**: DRAFT | **Created**: 2026-08-05
> **Severity**: medium | **Category**: L2 package/test adaptation

## Error surface

This pattern appears when adapting LuaRocks 3.13.0 against a Lua 5.5 runtime:

```text
Error: Could not satisfy dependency lua >= 5.1, < 5.5
Missing dependencies for luacov 0.15.0-1:
   lua >= 5.1, < 5.5 (not installed)
```

The submitted package can still build and run, but the upstream Busted test
suite is no longer a valid Path A proof because one of the upstream test
dependencies excludes Lua 5.5. In the `luarocks5.5/3.13.0` adaptation, the
reproduced upstream Busted run reached 55 cases from 43 files: 52 passed, 3
were skipped, and setup/integration errors were produced while installing
`luacov 0.15.0-1`.

Two secondary runtime packaging symptoms were also useful to capture:

- OHOS worker Lua may fail `os.tmpname()` with "unable to generate a unique
  filename" when no suitable temporary path is available.
- A Conan `test_package` that invokes bare `luarocks` can fail if the run
  environment PATH is not applied exactly as expected; invoking the packaged
  command by absolute path is more robust.

## Root cause

LuaRocks 3.13.0 itself supports `--lua-version=5.5`, but the upstream test
harness depends on `luacov` and `busted-htest`. The published `luacov
0.15.0-1` rockspec declares `lua >= 5.1, < 5.5`, which conflicts with the task
target `lua/5.5.0`.

This is a test-dependency compatibility problem, not proof that the packaged
LuaRocks commands are unusable. The self-written Conan consumer tests must
therefore stay separate from upstream-test accounting.

## Recommended handling

1. Use Path B instead of claiming Path A if every upstream case cannot execute
   and pass under Lua 5.5.
2. Record the exact upstream inventory and original Busted result, including
   the failing dependency range for `luacov 0.15.0-1`.
3. Keep the package recipe functional for Lua 5.5 with explicit configure
   options:

   ```bash
   ./configure --prefix=/ --sysconfdir=/etc --force-config \
     --lua-version=5.5 \
     --with-lua-bin=<lua/5.5.0>/bin \
     --with-lua-include=<lua/5.5.0>/include \
     --with-lua-lib=<lua/5.5.0>/lib
   ```

4. Make installed `luarocks` and `luarocks-admin` launchers relocatable:
   derive the install prefix from `arg[0]`, reset LuaRocks hardcoded paths, and
   use a Lua module search pattern that matches `luarocks.*` with `^luarocks%.`.
5. Patch packaged `luarocks/core/util.lua` so temporary-name creation prefers
   `TMPDIR`, `TMP`, or `TEMP` before falling back to `os.tmpname()`.
6. In `test_package`, first verify packaged artifacts exist, then execute the
   packaged commands by absolute path. Cover both positive smoke behavior and a
   deterministic negative/fault-injection case.

## Validation checklist

For `luarocks5.5/3.13.0`, a sufficient consumer check should cover:

- `luarocks --version`
- `luarocks config lua_version`
- `luarocks-admin --version`
- `luarocks help install`
- an invalid LuaRocks command returning non-zero
- an invalid rockspec lint returning non-zero

The official CI run for PR #3886 build #13356 verified the package recipe and
consumer tests before this knowledge entry was added: `conan create` passed,
`test_package` executed, and the log included `luarocks5.5 smoke and
fault-injection checks passed` plus `L0_RESULT=pass`, `L1_RESULT=pass`,
`L2_RESULT=pass`, and `L5_RESULT=pass`.

## Non-weakening rule

Do not count `test_package` checks as upstream Busted cases. The consumer tests
prove the packaged artifact runs; they do not convert a Lua 5.5-incompatible
upstream test dependency into a Path A pass.
