# E237: HarmonyOS PC ACPI 接口缺失（acpid 类守护进程适配模式）

> **Contributor**: junshi_liu | **Status**: Verified | **Updated**: 2026-08-04
> **Severity**: 2 | **Category**: runtime / platform-diff / system-service

## 错误特征

HarmonyOS PC（HongMeng Kernel 1.12.0 aarch64）上，/proc/acpi、/sys/bus/acpi、
/sys/firmware/acpi 均不存在，/proc/net 中无 NETLINK_GENERIC。
acpid 运行期无事件源可读，守护进程实际不可运行（编译期正常通过）。

## 触发条件

- 阶段：runtime
- 平台：HarmonyOS PC aarch64（HongMeng Kernel 1.12.0）
- 典型工具：acpid、acpi_listen、kacpimon、powertop 等依赖 ACPI 接口的守护进程

## 根因分析

HarmonyOS PC 内核不提供 Linux 标准 ACPI 用户态接口。acpid 编译期只依赖
libc 与标准头文件，configure/make 全通过；运行期依赖 /proc/acpi 等接口
接收电源/合盖/电池事件，接口缺失则无事件源可读。

## 解决方案

### 推荐方案（三级决策）

1. 仅编译验证（积分赛适配基线）：发布可执行包，在 notes/PR 中声明 ACPI 缺失
2. 运行期探测降级：patch event.c，启动时探测接口，全部缺失则打印诊断日志后退出
3. 平台 shim：若 HarmonyOS 有替代电源事件接口（hdf/udev），写适配层翻译事件

### probe 阶段结论

采用方案 1（仅编译验证），不虚构可运行结论。

## 验证命令

```bash
ls /proc/acpi/ 2>&1 || echo "MISSING: /proc/acpi"
ls /sys/bus/acpi/ 2>&1 || echo "MISSING: /sys/bus/acpi"
ls /sys/firmware/acpi/ 2>&1 || echo "MISSING: /sys/firmware/acpi"
uname -r   # HongMeng Kernel 1.12.0
```

## 实测输出（2026-08-04，executor pc2-2）

- /proc/acpi/ → No such file or directory
- /sys/bus/acpi/ → No such file or directory
- /sys/firmware/acpi/ → No such file or directory
- uname -r → HongMeng Kernel 1.12.0

## 复用范围

HarmonyOS PC 平台上所有依赖 ACPI 事件接口的守护进程/工具适配判断。
