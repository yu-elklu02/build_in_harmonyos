# E217: CMake 上游头文件装到 include/<subdir> 导致 test_package 找不到头文件

## 基本信息
- **严重度**: 2
- **类别**: cmake|conan-recipe|header-path
- **触发工具**: conan|cmake
- **阶段**: conan-verify (test_package build)

## 错误特征
```
fatal error: '.+\.h' file not found|test_package.*\.c:\d+:\d+: fatal error
```

**关键词**: file not found, includedirs, test_package, header, CMakeLists install

## 根因分析
上游 CMake 用 install(FILES ${c_headers} DESTINATION include/${PROJECT_NAME}) 把头文件装进 include/<subdir>，但 conan-init 生成的模板配方 package_info() 默认 includedirs=["include"]，test_package 的 #include <xxx.h> 找不到头文件，G2 在 test_package 阶段失败。知识图谱仅匹配到 E001（找不到编译器），根因完全不同，属误匹配。

**影响范围**: 所有 CMake 工程头文件安装到 include/<subdir>（如 include/libairspyhf、include/libusb-1.0）且 test_package 以顶层 <subdir>/../ 形式 include 的场景

## 修复方案
**推荐方案**: 先读上游 CMakeLists 确认 install(FILES ... DESTINATION) 目标目录，再把 package_info() 的 cpp_info.includedirs 指向实际子目录（如 ["include/libairspyhf"]），与上游工具源码的 #include <airspyhf.h> 保持一致

修正 package_info includedirs 指向实际头文件子目录后重跑 conan-verify

**命令**: grep -rn "DESTINATION include" <src>/CMakeLists.txt && 修改 conanfile.py package_info() includedirs
