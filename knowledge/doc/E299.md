# E299 - Conan 源码获取失败的分层诊断

## 使用说明

当 Conan `source()`/`tools.files.get()` 报源码下载失败时，先用本条目判断失败属于网络传输、URL、权限还是完整性校验，再选择修复方案。不要直接采信机器人生成的“网络问题”摘要。

## 适用范围

- `conandata.yml` 声明上游源码 URL 和 SHA256。
- 配方通过 Conan `get()` 下载 release 包。
- CI 使用多个镜像 fallback，或同一错误在多个 Worker 上表现不同。
- 错误日志同时出现 `Could not download`、HTTP 状态或 `sha256 hash failed`。

## 输入定义

- 完整 `conan source`/`conan create` 日志，而不是截断后的机器人摘要。
- `conandata.yml` 中的官方 URL 和 SHA256。
- 上游 release 页面、签名或校验文件。
- 多镜像返回的 Provided/Computed hash。

## 输出定义

- 明确的错误分类和对应修复动作。
- 可审计的官方 release 或权威镜像 URL。
- 从可信上游发布物独立验证的 SHA256。
- 不再把哈希、404 或后续构建失败误报为网络问题。

## 分层判断

| 日志证据 | 分类 | 处理 |
|----------|------|------|
| `curl (28)`、`timed out`、`Could not resolve host`、TLS/连接错误 | 真网络问题 | 重试 Worker，检查 DNS/TLS；GitHub 类问题关联 E017；使用 CI 已配置的镜像 fallback |
| HTTP 404/403，且域名可连接 | URL/权限问题 | 核对版本、release 资产名、重定向和访问权限 |
| `sha256 hash failed`，多个镜像的 Computed hash 一致 | 配方哈希错误或上游发布物变更 | 从官方 release/签名重新验证正确 SHA256；不能按网络问题处理 |
| 不同镜像返回不同 Computed hash | 镜像内容不一致或缓存污染 | 停止使用异常镜像，以官方发布物为准并报告镜像问题 |
| `Sources correctly downloaded` | 源码阶段成功 | 继续向后检查解压、补丁、configure、编译或测试，不能再诊断为下载失败 |

## 解决步骤

1. 从完整日志定位首个失败点，不使用 Build Summary 的泛化提示替代根因。
2. 记录 URL、HTTP/传输错误、Provided hash 和 Computed hash。
3. 对照上表分类。
4. 保持 `conandata.yml` 使用官方 release 或权威镜像（R39）。GitHub URL 的镜像 fallback 由 CI 自动添加，不要手工写个人代理前缀。
5. 对 SHA256 错误，从可信上游重新下载并独立计算；先验证来源，再修改哈希。
6. 重新执行 `conan source`，随后执行完整 `conan create`，确认问题没有移动到后续阶段。

```bash
conan source path/to/recipe -v
sha256sum upstream-release.tar.gz
conan create path/to/recipe
```

## 禁止做法

- 看到 `Could not download` 就统一归类为网络问题。
- 把 `sha256 hash failed` 当成网络超时并不断更换镜像。
- 为绕过 Worker 网络使用个人 GitCode blob、网盘或滚动 `main/master` 源码。
- 未核实上游发布物就把配置改成日志中的 Computed hash。
- 日志已经出现 `Sources correctly downloaded` 后仍修改源码 URL。

## 验证证据

PR #2063 的 CI #2228 中，mcpp 当时从个人 GitCode blob URL 成功下载并进入构建测试；该地址本身不符合最终采用的 R39 来源策略。同一构建里的 nettle 在清华、USTC、阿里三个镜像均得到相同 Computed hash，但 Provided hash 不同，实际阻塞是配方 SHA256 错误，不是网络不可达。

机器人将该构建概括为“源码下载失败/网络问题”，会掩盖哈希根因并诱导继续更换非官方镜像。最终 PR 移除误混入的 nettle，并恢复 mcpp 官方 SourceForge URL；CI #3530 成功下载、校验并完成构建。

## 与现有知识的边界

- E017：处理已由日志证明的 GitHub/DNS/连接超时。
- E222：在进入 E017 之前先区分网络、URL、哈希和后续阶段失败，作为 E017 的诊断前置。
- R39：源码 URL 必须是官方正式源或权威镜像，禁止个人 fork、网盘和不明 CDN。
