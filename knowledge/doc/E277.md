# E277 — vendored/bundled 依赖的构建模式

## 错误特征

三方库 `requires` 一个依赖，但该依赖未发布到 OHOS 制品仓（ohpcd）、仓库内无现成 Conan 配方，且上游源码包已自带该依赖的完整源码（vendored/bundled）。典型报错：

```
ERROR: Required library libmodbus not found
ERROR: Package 'glib/2.84.0' not resolved: Unable to find 'glib/2.84.0' in remotes
configure: error: popt library required
```

## 触发条件

- 构建系统：autotools / cmake / meson（任一，子项目与主库可不同）
- 阶段：configure（主库找不到依赖）/ installation
- 适用：上游源码包内含依赖源码（如 `archives/m/mbpoll/1.5.4/libmodbus/`）

## 根因分析

OHOS 制品仓覆盖的依赖有限，大量小众库（libmodbus、popt、apr、libssh、msgpack-c 等）没有预编译包也无配方。但这些库常作为更大库的 vendored 依赖随源码下发。CI worker 环境差异大，不能假设系统提供（`/root/sysnc`、`/usr/lib` 等非标准路径在不同 worker 上有/无）。

## 解决方案

### 推荐方案：build vendored 子项目到 staging

在 recipe 的 `build()` 里，先把 vendored 依赖源码编译为**静态库**，install 到 `build_folder` 下的 staging 目录，主库再引用 staging 的头文件和库链接：

```python
def _build_vendored(self):
    dep_src = os.path.join(self.source_folder, "<dep>")  # vendored 源码目录
    prefix = os.path.join(self.build_folder, "<dep>-root")  # staging
    self.run(f"./configure --prefix={prefix} --disable-shared --enable-static "
             f"--build=<triplet>", cwd=dep_src)
    self.run("make install", cwd=dep_src)

def generate(self):
    tc = AutotoolsToolchain(self)  # 或 CMakeToolchain
    prefix = os.path.join(self.build_folder, "<dep>-root")
    tc.extra_cflags.append("-I" + os.path.join(prefix, "include"))
    tc.extra_ldflags.append("-L" + os.path.join(prefix, "lib"))
    env = Environment()
    env.define_path("PKG_CONFIG_PATH", os.path.join(prefix, "lib", "pkgconfig"))
    tc.generate()
```

要点：
1. **静态链接**：子项目 `--disable-shared --enable-static`，避免运行时 .so 依赖链和代码签名负担
2. **staging 隔离**：install 到 `build_folder/<dep>-root`，不污染系统，主库通过 `-I`/`-L` 显式引用
3. **显式三元组**：子项目 configure 传 `--build=<triplet>`，避免 config.guess 探测失败（HMDFS 下尤其）
4. **PKG_CONFIG_PATH**：主库若用 `pkg_check_modules` 找依赖，把 staging 的 pkgconfig 加进去
5. **manifest 如实声明**：vendored 依赖在 `manifest.yaml` 的 `vendored_deps` 列出

### 禁止做法

- ❌ **假设系统提供**：如直接用 `/root/sysnc/lib/libncurses.a`——不同 worker 环境差异大，非标准路径不可靠
- ❌ **vendored 依赖动态链接**：`--enable-shared` 会让 .so 进产物，需单独代码签名 + 运行时 LD_LIBRARY_PATH
- ❌ **手动 copy .o/.a 到产物**：必须走 `make install` 到 staging 再由 Conan package 打包

## 验证

```bash
# 确认 vendored 依赖被静态链接进主库（无独立 .so）
readelf -d <主库或可执行> | grep NEEDED  # 应只见 libc.so 等
# 确认 staging 产物
ls build/<dep>-root/lib/*.a
```

## 实际案例

| 库 | vendored 依赖 | 处理 |
|----|--------------|------|
| mbpoll 1.5.4 | libmodbus 3.1.7 | build() 内 configure+make install 到 `libmodbus-root`，主库 CMake 经 `PKG_CONFIG_PATH` 找 |
| logrotate 3.22.0 | libpopt | 编译 popt 到 `poptinst`，logrotate configure 用 `-I/-L` 指向 |
| log4cxx 1.7.0 | apr + apr-util + expat | `_build_autotools` 依次编译三个子项目到 staging |
| tmate 2.4.0 | libssh + msgpack-c + mbedtls + ncurses | 内联构建四个依赖静态库 |
