# E231: Direct-copy recipes can omit generated public headers


## Symptom

A header-oriented Conan package builds and its include tree looks populated,
but a downstream consumer cannot include a public header documented by the
upstream installation:

```text
fatal error: 'X11/Xpoll.h' file not found
```

The recipe often reports exactly the number of `.h` files already present in
the source archive, which can make the package appear complete.

## Root cause

The recipe bypasses the upstream configure/build step and copies `*.h` directly
from the source tree. Upstream CMake, Meson, or Autotools rules may also install
headers generated in the build directory from `.in` templates. Some templates
substitute results from target compiler probes, so copying the template or
hardcoding the developer machine's result is not equivalent.

Clearing the entire Conan package ID compounds the error when the generated
header depends on the target libc, ABI, architecture, or compiler headers.

## Fix

1. Inspect every upstream build system's installation definitions for both
   static and generated headers.
2. Run the upstream configure phase, or reproduce its minimal probe using only
   the target compiler declared by the Conan profile.
3. Require a unique successful probe result and substitute the original
   template into the build directory.
4. Package the generated output alongside static headers.
5. Retain package ID settings that can affect generated content.
6. Add a consumer that expands the generated macro or accesses the probed
   member; an include-only smoke test may not instantiate the faulty code.

For xorgproto 2025.1, both Meson and Autotools generate `X11/Xpoll.h` after
probing `fd_set.fds_bits` and `fd_set.__fds_bits`. The Conan recipe probes those
members with `tools.build:compiler_executables[c]`, generates the header from
`Xpoll.h.in`, and tests `descriptor_set.__X_FDS_BITS` under `-Werror`.

## Validation

Compare the packaged include inventory with upstream install declarations,
then perform a fresh target build and compile the substantive consumer:

```bash
grep -R -E 'configure_file|AC_CONFIG_FILES|install_headers|HEADERS.*=' .
conan create <recipe-dir> -pr:h=<target-profile> -pr:b=<target-profile> --build='*'
```

Do not count the fix as validated until the generated header exists in the
package and its target-sensitive token is compiled by the target toolchain.
