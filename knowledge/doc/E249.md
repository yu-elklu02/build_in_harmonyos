# E249: 未初始化所有权标志导致清理函数释放调用者栈对象

> **Contributor**: tianyi_wang | **Status**: Verified | **Updated**: 2026-07-13
> **Severity**: 3 (blocking) | **Category**: c-ownership-uninitialized-state

## 错误特征

核心转换完成并已生成输出文件，但进程在清理阶段报告 `Signal 11 (core dumped)`、退出 139。ASan 可报告 `attempting free on address which was not malloc()-ed`，地址位于调用者栈帧中的对象。

## 触发条件

- 阶段：运行时核心数据转换结束后的资源清理
- 代码模式：子对象保存调用者对象指针，清理行为由 `shared`/`owned` 标志决定
- 必要输入：必须实际创建子对象内容；空输入或帮助路径不会触发缺陷

## 根因分析

构造路径为子对象设置了调用者持有的对象指针，但未初始化所有权标志。清理函数读取不确定值，在标志表现为"独占"时关闭并 `free()` 该借用指针。若指针指向调用者栈对象，会发生 invalid free；随后调用者还可能再次清理同一对象。

FASTGA 1.5 中，`Create_GDB()` 为检测到小写掩码的 FASTA 构造 `ANO`，将 `ano->gdb` 指向 `FAtoGDB` 栈上的 `GDB`，却未设置 `ano->shared`。`Free_ANO()` 因此可能执行 `free(ano->gdb)`，官方 `HAP1.fasta.gz` 稳定触发退出 139。

## 解决方案

### 推荐方案

在建立借用关系时明确设置 `shared = 1`（或项目等价的 borrowed 标志），保留调用者作为唯一释放方。回归测试必须使用能产生子对象内容的确定输入，并检查转换退出 0 和核心输出非空。

### 禁止做法

- 仅测试 `--help` 或不产生子对象的最小输入。
- 因输出文件已出现而忽略退出 139。
- 在清理函数中无条件跳过释放，掩盖真实所有权契约。

## 验证

```bash
TMPDIR="$PWD" ASAN_OPTIONS=symbolize=1 ./FAtoGDB-asan HAP1.fasta.gz HAP1
test -s HAP1.1gdb && test -s .HAP1.bps
```
