# E254: toybox patch --dry-run 真实应用 new-file 补丁，破坏补丁管线

> **Contributor**: mkz--mkz | **Status**: Verified | **Updated**: 2026-08-05
> **Severity**: 3 (blocking) | **Category**: tool-compat / patch-pipeline

## 错误现象

`refresh-patch --auto` 生成的补丁被 `conan create` 的 `apply_conandata_patches()` 拒绝：

```text
ConanException: Failed to apply patch: .../patches/0002-xxx.patch
source/target file does not exist
```

## 根因

HarmonyOS 默认 `/usr/bin/patch` 是 **toybox 0.8.12**。实测确认：

```sh
$ printf '--- /dev/null\n+++ b/new.txt\n@@ -0,0 +1,2 @@\n+hello\n+world\n' | patch --dry-run -p1
creating new.txt        # ← dry-run 却真实创建了文件！
```

toybox 的 `patch --dry-run` 对 **new-file 补丁**会真实创建文件，忽略 dry-run 语义。
`refresh-patch` 的 dry-run 校验因此污染 `orig/` 目录，下一轮扫描把该文件误判为 MOD，
生成带 `a/` `b/` 前缀的 diff，`patch_ng` 无法应用。

## 推荐方案：新增源码走 export_sources

把新增的源码从补丁移出，改为 conanfile.py `export_sources()` 传递；`conandata.yml`
只保留修改文件的补丁：

```python
def export_sources(self):
    export_conandata_patches(self)
    copy(self, "*", src=os.path.join(self.recipe_folder, "compat"),
         dst=os.path.join(self.export_sources_folder, "compat"))
```

## 验证

```sh
printf '--- /dev/null\n+++ b/t.txt\n@@ -0,0 +1,1 @@\n+x\n' | patch --dry-run -p1
ls t.txt 2>/dev/null && echo "被真实创建"
```

## 案例

- abiword-plugin-clarisworks 3.0.8（2026-08-05）：改 export_sources 后 conan create 全绿
