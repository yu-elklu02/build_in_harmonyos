# E275 — OHOS shell grep -v 空结果触发 set -e 退出

## 错误特征

```text
grep -Fv -- "${_envfile}:" "${AUTOENV_AUTH_FILE}.tmp" >| "${AUTOENV_AUTH_FILE}"
ConanException: Error 1 while executing
```

在 `set -e` 的 shell 测试或安装脚本中，`grep -v` 用于过滤授权文件、缓存文件等内容时，如果输入为空或全部被过滤，`grep` 会返回 1。该返回码表示“没有输出”，但会被 `set -e` 当成失败并提前退出。

## 触发条件

- 构建系统: shell/custom
- 阶段: test/install/runtime smoke test
- 平台: OHOS shell 环境或其他严格 `set -e` 环境

## 根因分析

`grep -v` 的退出码语义不是单纯的命令执行成功/失败。没有匹配输出时返回 1 是正常业务结果，但 `set -e` 会把非零退出码当成脚本错误，导致后续授权、写文件或 source 流程中断。

## 解决方案

### 推荐方案

对允许空结果的过滤步骤追加 `|| :`，明确声明“无输出是正常结果”：

```sh
grep -Fv -- "$pattern" input > output || :
```

如果模式来自固定字符串，优先使用 `grep -F`，避免路径、冒号或其他字符被正则解释。

### 禁止做法

- 不要整体关闭 `set -e` 来掩盖错误。
- 不要忽略输出文件写入，过滤命令仍应保留重定向结果。

## 验证

```bash
sh -x test_package/test.sh
conan create archives/a/autoenv/0.4.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
