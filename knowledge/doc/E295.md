# E295 — sign-elf 缺失导致 ELF 证据降级为 probe-only（无法证明鸿蒙签名门禁满足）


## 验证命令与真实结果

```bash
command -v sign-elf        # → 无输出（不存在）
echo rc=$?                 # → rc=1
ls /usr/bin/sign-elf /usr/local/bin/sign-elf   # → 系统路径均无
```

- 未安装、未伪造签名工具（未 `apt/ln` 等创建假工具）。

## 对 ELF 签名 / .codesign / 运行和交付的影响

- 鸿蒙 ELF 可执行文件必须包含有效 `.codesign` 签名段才能被内核加载执行（关联 E077）。
- 缺少 sign-elf 时，产物 `libopenal.so` 等**未签名**，无法证明可交付 ELF 满足鸿蒙签名门禁。
- 因此以下结果**只能作为探针证据**，不能证明交付门禁完成：
  - 上游测试：`ctest --test-dir build-tests --output-on-failure -V` → 1/1（100%）
  - Conan test_package：编译/运行全 PASS，0 failures
  - Null/loopback 无设备验证：0 failures，退出码 0
  - 打包产物（PackageBuilder 生成的 release/debug tar.gz）

## 允许的静态检查

- `readelf -S libopenal.so | grep -i codesign`（检查是否存在 `.codesign` 段）。
- 如实记录"未签名 / 未完成签名门禁"。

## 禁止做法

- ❌ `skip sign`（跳过签名）。
- ❌ `chmod 777`（不产生签名段）。
- ❌ 用本地主机可运行替代签名工具（非官方工具链，无法保证内核认可）。
- ❌ 把该工具缺失自动申报为 HarmonyOS 系统差异专项或路径 C（工具环境问题，非系统能力差异新发现）。

## 重复/关联说明

- 与既有条目部分重复属预期：E077（.codesign 段要求）、E088（动态链接器 namespace，同类工具链/运行时限制）已存在；本条目保留"工具缺失导致证据降级为 probe-only"的组合场景，待维护者审核，不因重复放弃沉淀。

## 恢复条件

官方执行环境提供 `sign-elf` 或框架认可的等价签名工具后：
1. 重新签名产物；
2. 重跑相关测试（上游 ctest / test_package / Null-loopback 替代验证）；
3. 重跑打包（PackageBuilder）与门禁（conan create / conan-verify / finish / W3）。

届时探针证据方可升级为可交付门禁证据。

## 关联条目

- E077：鸿蒙 ELF 需有效 `.codesign` 签名段（similar_to）。
- E088：动态链接器 namespace 配置（similar_to，同类工具链/运行时限制）。
- E216 / E217：openal-soft 1.25.2 同库条目。
