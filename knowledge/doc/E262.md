# E262: Reserved scratch aliases must be classified before strict parent resolution

> **Contributor**: 2301_80739235 | **Status**: Verified | **Updated**: 2026-08-08
> **Severity**: 3 (blocking) | **Category**: filesystem / symlink / scratch / path-policy / security

## Symptom

A wrapper should reject `scratch-alias/output` because `scratch-alias` points
to its reserved `.t` tree. When `.t` does not exist yet, strict parent
resolution instead raises `FileNotFoundError` and the wrapper reports a generic
missing output directory.

## Root Cause

Path normalization and safety classification occur in the wrong order. A
strict resolver requires the final parent to exist, but a safety policy must be
able to classify the destination even when the reserved scratch directory has
not been created. The early filesystem error masks the intended policy result.

## Fix

1. Keep strict resolution for ordinary usable destinations.
2. When strict resolution fails, run a policy-only resolver that walks path
   components, follows links explicitly, detects loops, and tolerates a missing
   final parent.
3. If the candidate is the scratch tree or lies below it, return it to the
   existing safe-destination gate.
4. Preserve the ordinary missing-directory result for unrelated paths.

## Forbidden Shortcuts

- Do not create the scratch directory merely to make strict resolution pass.
- Do not weaken the reserved-output policy for symlinked paths.

## Validation

GraalVM 25.0.3 implements this in
`archives/g/graalvm/25.0.3/files/native_image_wrapper.py` and covers both the
policy result and the unrelated missing-parent control in PR #3928.
