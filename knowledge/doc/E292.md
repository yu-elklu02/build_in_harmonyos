# E292 — 大型 C++ 数据处理库上游 CTest/GTest 在 OHOS 上的分层迁移

## 错误特征

大型 C++ 库的上游测试在 OHOS 真机或 Conan 交叉环境中出现多类组合问题:

```text
/tmp/gtest_captured_stream.* 创建失败
Please point the PARQUET_TEST_DATA environment variable to the test data directory
Test resources not found, set ARROW_TEST_DATA
Cannot locate timezone ... discover_tz_dir failed to find zoneinfo
std::ranges::equal 编译失败
Error loading shared library ../../release/libarrow_gtest.so
duplicate libarrow_gtest / libarrow_gmock 后测试通过但进程退出 133
make: jobserver mkfifo: Operation not permitted
posix_fadvise failed. errno 22 Invalid argument
OpenAppendStream("abc/") 平台行为与上游预期不一致
OOM 用例期望 std::bad_alloc / OutOfMemory, 实际未抛异常、返回 OK 或 Signal 11
gRPC tarball 解包 symlink/hardlink 条目失败, Permission denied
Flight/gRPC 配置阶段缺少 OpenSSL::SSL / OpenSSL::Crypto
```

这些现象通常不是单个 recipe 参数能解决的问题, 而是测试框架、测试资源、动态加载路径、标准库能力和系统文件语义同时作用的结果。

## 触发条件

- 阶段: 上游测试构建和执行。
- 工具: CMake/CTest/GTest/Conan。
- 典型库: Apache Arrow 这类多模块 C++ 数据处理库。
- 环境: HarmonyOS 真机 aarch64, OHOS SDK clang/libc++ 15, Conan 隔离构建。

## 根因分析

Linux 开发机默认具备的测试前置条件在 OHOS CI/真机环境中并不完整:

- GTest 默认临时目录 `/tmp` 不可写或不可访问。
- release 源码包可能不包含完整官方测试数据。
- timezone 数据路径不是 Arrow/date 库可自动发现的 IANA 目录。
- 系统自带 zoneinfo 目录即使存在, 也可能与上游测试期望或 IANA 数据版本不一致, 需要与可控 tzdb 来源对照。
- OHOS LLVM 15 libc++ 对部分 C++20 ranges 算法支持不足。
- HarmonyOS loader 对测试构建树中的相对 `NEEDED` 路径解析不同; 直接复制多份测试动态库可能导致同一进程重复加载 GTest/GMock, 并在 `RUN_ALL_TESTS()` 返回前触发 SIGTRAP / 133。
- make jobserver FIFO 在当前用户目录文件系统中受限。
- 当前真机文件系统可能不允许创建 symlink/hardlink, 导致 gRPC 这类带 link 条目的源码包在 CMake/libarchive FetchContent 解包阶段失败。
- 文件系统和 libc 的边界行为与 Linux 预期存在差异。
- allocator / 虚拟内存 overcommit 的极限分配语义可能与上游 Linux 测试期望不一致。
- Flight/gRPC 会牵出 protobuf、re2、zlib、OpenSSL/BoringSSL 等额外依赖, 且服务式测试还需要端口或 socket 运行环境。

因此, 对此类库不能只做 smoke test, 也不能将 `test_package` 通过写成完整上游测试通过。

## 推荐方案

### 1. 建立上游测试 inventory

先按测试入口而不是粗略 case 数统计:

- 标准 CTest target 数量。
- 可在当前 OHOS 环境迁移执行的 C++ target。
- 需要额外数据、服务、语言运行时或硬件的 target。
- 暂不执行子集及原因。

Apache Arrow 24.0.0 示例:

- 核心模块: 52 个 CTest target。
- Parquet 新增: 11 个 target。
- Dataset/Acero 新增: 26 个 target。
- 最大完成范围: 89 个 target, 81 个通过。

### 2. 补齐测试运行环境

可迁移 C++ 子集通常需要:

```bash
export TMPDIR="$PWD/tmp"
export ARROW_TEST_DATA="$ROOT/testing/data"
export PARQUET_TEST_DATA="$ROOT/cpp/submodules/parquet-testing/data"
export TZDIR="$HOME/.local/lib/python3.12/site-packages/tzdata/zoneinfo"
export LD_LIBRARY_PATH="$BUILD/relinked-needed-run:$LD_LIBRARY_PATH"
ctest -j1 --output-on-failure
```

实际路径需按隔离工作目录调整。若 GTest 版本在非 Android/Linux 分支硬编码 `/tmp`, 可临时补丁测试框架优先读取 `TEST_TMPDIR` / `TMPDIR`; 若 vendored date 只查固定系统 zoneinfo 路径, 可增加通用 `TZDIR` 支持, 让测试和下游运行时能显式提供 IANA tzdb。

timezone 相关 target 需要进一步记录 tzdb 来源和版本。Apache Arrow 24.0.0 的 temporal 探针显示, Python `tzdata 2026.3` 的 zoneinfo 是当前真机上最稳定的输入; 系统 `/etc/zoneinfo` 或 unset `TZDIR` 会扩大失败范围, 因此不宜简单把系统目录写成默认回退。

若测试二进制或 `libarrow_testing.so` 的 `NEEDED` 记录了 `../../release` / `../../../release` 这类相对路径, 不要用多目录复制测试库的方式规避加载失败; 应重新链接测试辅助库和测试二进制, 使 `NEEDED` 统一为 `libarrow_gtest.so`、`libarrow_gmock.so` 等 basename, 并只提供一个测试动态库目录。扩展测试应优先单线程或受控并发, 避免 make jobserver FIFO 限制造成误判。

若重依赖模块使用 FetchContent 下载第三方源码包, 还需要检查源码包解包形态。gRPC 1.46.3 tarball 包含 symlink/hardlink 条目, 当前真机文件系统拒绝 link 创建时, 可用 no-links 预解包方式将 link 条目展开为普通文件或目录副本, 再通过 `FETCHCONTENT_SOURCE_DIR_GRPC` 传入 CMake。该方法只证明能越过解包层, 不等价于 Flight/gRPC 测试通过; 若随后缺少 OpenSSL/BoringSSL, 应继续记录为依赖闭环缺口。

### 3. 对平台差异采用窄范围修复

能够稳定归因到库层兼容的差异, 优先使用 POSIX 兼容的通用防御逻辑或 recipe 配置做窄范围修复。

Apache Arrow 24.0.0 示例:

- 在 Arrow `ReadRange` 语义下跳过零长度 `ReadableFile::WillNeed` range, 避免把空 range 传给 OS read-ahead advice。
- 拒绝目录尾斜杠 path 作为 `OpenOutputStream` / `OpenAppendStream` 目标, 保持输出流目标必须是文件的契约。
- 固定 CMakeDeps target 为 `Arrow::arrow`, 同时保留 shared/static alias。

不应为了提高通过率扩大为禁用全部 `fadvise` 或跳过完整测试 target。

### 4. 诚实区分三类结果

路径 B 材料中应分开写:

- 上游原样或迁移后 CTest 子集结果。
- 消费者 `test_package` 结果。
- 未执行或未通过子集的原因。

不要将替代验证、过滤项验证或 `test_package` 冒充完整上游测试通过率。

## 验证参考

Apache Arrow 24.0.0 已验证:

- Parquet 聚焦: 11/11 passed。
- Dataset/Acero 聚焦: 26/26 passed。
- 最大扩展 CTest 范围: 81/89 passed。
- P1 文件 IO / Filesystem 重新链接测试工具链后: `arrow-io-file-test` 50/50 passed, `arrow-filesystem-test` 198/198 passed。
- `arrow-array-test` 经 GTest TMPDIR 迁移后: 1038 passed, 1 skipped。
- `arrow-buffer-test` / `arrow-misc-test` / `arrow-stl-test` 排除已定位 OOM 缺口后: 45/45, 180/180, 44/44 passed。
- OOM/allocator 单用例探针: `allocator.TestOOM` 未抛 `std::bad_alloc`; `TypedTestBuffer/0.ResizeOOM` 为 `Signal 11`; `Default/TestMemoryPool/0.OOM` 返回 OK 而非 `OutOfMemory`。
- `arrow-compute-scalar-cast-test` 新增 `TZDIR` 支持后: 105/106 passed; 非 timezone 子集 103/103 passed。
- 低风险增量复验: `arrow-scalar-test`、`arrow-compute-internals-test`、`arrow-generator-test`、`arrow-gtest-util-test`、`arrow-random-test` 合计 627 passed, 14 skipped。
- compute-on 专项: 新建 `ARROW_COMPUTE=ON` 测试树, 显式指定 aarch64/arm64/aapcs 避免 Boost.Context 误选 x86_64 汇编; 12 个 compute target 完整通过, 合计 3272 passed, 25 skipped。
- `arrow-compute-scalar-temporal-test`: 全量 54 tests 中 46 passed, 1 skipped, 7 个历史 timezone/DST 规则差异失败; 过滤已定位差异后 46 passed, 1 skipped。
- temporal DST 对照探针: Python `tzdata 2026.3` 下主体用例保持 46 passed, 1 skipped; `/etc/zoneinfo` 或 unset `TZDIR` 扩大为 17 failed。
- ORC 首轮探针: 配置阶段进入 Protobuf FetchContent 后在 1200 秒上限退出, 记录为 ORC/protobuf 重依赖边界。
- Flight 首轮探针: gRPC 1.46.3 下载完成后因 symlink/hardlink 创建受限解包失败; no-links 预解包 12 个 link 条目后越过解包层; 静态 Arrow 测试树配置完成后停在 `OpenSSL::SSL` / `OpenSSL::Crypto` target 缺失。
- shared/static Conan 消费验证通过。
- 增强 `test_package`: 15 个可观测断言通过。

## 禁止做法

- 不要只运行 `test_package` 就声明上游测试通过。
- 不要把 CTest target 子集通过率写成完整 Path C 通过率。
- 不要跳过未通过 target 后不说明原因。
- 不要为了消除单个失败而引入过宽的库行为 patch。
