# E228: Conditionally launch extensionless Libtool test wrappers on HMDFS

> Contributor: 1catmint1 | Status: DRAFT | Created: 2026-07-19

## Symptom

`make check` reports many `Permission denied` failures before the tested code
runs. The failing path looks like a test executable and has no `.sh` suffix.
Running the same path through `/system/bin/sh` reaches the real test program.

## Root cause

Libtool dynamic-link tests use two files with the same basename:

- `test/name`: an extensionless shell wrapper;
- `test/.libs/name`: the real ELF.

HMDFS can prevent direct execution of the generated wrapper. E087 covers
ordinary `.sh` files, but an extension-based rule misses these wrappers.
Conversely, static and non-Libtool tests are real ELF files and must not be
passed to a shell unconditionally.

## Fix

Provide an Automake `LOG_COMPILER` launcher. For the first test argument, check
whether a sibling `.libs/<basename>` exists. Use the configured HarmonyOS shell
only for that wrapper case; otherwise execute the original test directly:

```sh
test "$#" -ge 1 || exit 125
candidate="${1%/*}/.libs/${1##*/}"
if test -f "$candidate"; then
    exec /system/bin/sh "$@"
fi
exec "$@"
```

Invoke the launcher itself through the configured shell so its own execute bit
is not another HMDFS dependency.

## Forbidden shortcuts

- Do not set `LOG_COMPILER=/system/bin/sh` for the entire mixed test set.
- Do not skip every test that first reports `Permission denied`.
- Do not rely on `chmod +x` alone on HMDFS.

## Validation

libxcrypt 4.5.2 used the conditional launcher in fresh HarmonyOS Conan shared
and static builds. The unique upstream set completed with 54/54 PASS; the
static configuration passed 54/54 and the shared configuration passed its
52/52 selected entries, with zero skipped or unexpected terminal results.
Direct ELF tests continued to execute normally.
