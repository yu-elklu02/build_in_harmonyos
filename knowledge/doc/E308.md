# E230: Conan test source templates and the CI L0c suffix gate


## Symptom

A real Conan test package generates and compiles consumers from a template, but
CI fails before `conan create`:

```text
[fail] L0c: No test source files in test_package/
```

The test directory may contain `header_smoke.c.in`, `consumer.cpp.in`, or a
`.tmpl` file and a valid `conanfile.py`, so the failure can look inconsistent
with the actual test logic.

## Root cause

The current `ci/conan/build_and_test.sh` L0c contract searches at most two
levels below `test_package/` and accepts only files whose final suffix is one of:

```text
.c .cpp .cc .cxx .sh .py
```

It explicitly excludes `conanfile.py`. A template ending in `.c.in` or
`.cpp.in` does not match, even when `test_package.build()` will later read that
template and generate valid sources.

## Fix

Keep at least one substantive test input under an accepted final suffix and
make sure the test package actually exports and consumes it. For a C template:

```text
test_package/header_smoke.c.in -> test_package/header_smoke.c
```

Update all references together:

- `exports_sources` in `test_package/conanfile.py`;
- the template path read by `build()`;
- `test_package/MANIFEST.yml`;
- test reports and contest PR text.

Then run both the exact structural search and a fresh Conan build:

```bash
find test_package -maxdepth 2 \
  \( -name '*.c' -o -name '*.cpp' -o -name '*.cc' \
     -o -name '*.cxx' -o -name '*.sh' -o -name '*.py' \) \
  -not -name conanfile.py

conan create <recipe-dir> -pr:h=<profile> -pr:b=<profile> --build='*'
```

## Forbidden shortcuts

- Do not add an empty `test.c` or other dummy marker only to satisfy `find`.
- Do not add a source file that is never exported, compiled, or executed.
- Do not rename the template without updating every consumer and manifest.
- Do not place the only recognized source below L0c's two-level search depth.

Those shortcuts can pass the structural check while violating R34 or breaking
the actual Conan test.

## Validation

xorgproto 2025.1 initially used `header_smoke.c.in`; independent W4 reproduced
the deterministic L0c failure. Renaming the same substantive template to
`header_smoke.c` made the exact CI `find` rule return the file. A new HarmonyOS
PC run with a fresh directory and fresh Conan home then returned 0, compiled 83
distinct public-header objects, and validated all 29 pkg-config modules.
