# E294: Keep a shared package while restoring static-only upstream tests

> **Severity**: medium | **Category**: CMake / Conan / upstream testing

## Usage

Use this pattern when a library must be delivered as a shared Conan package,
but its CMake project creates the full upstream test suite only when
`BUILD_SHARED_LIBS=OFF`. The second build tree is test-only and must never be
installed into the package.

## Scope

- CMake-based C or C++ libraries packaged with Conan 2.
- The public shared target is the required delivery contract.
- Tests that use private/internal symbols are guarded by a static-build branch.
- Native OHOS builds can execute tests; Windows-to-OHOS builds can only compile
  and link target binaries.

This pattern does not apply when tests can already link the shared public API,
or when the project provides an explicit non-installed static test target.

## Inputs

- `source_folder`: one verified upstream source tree.
- `generators_folder/conan_toolchain.cmake`: the same Conan toolchain used by
  the package build.
- Project-specific CMake switches for tests, benchmarks, and installation.
- Exact test-source submodule commits and SHA256 values when release archives
  omit submodule contents.
- Conan `can_run()` result.

## Outputs

- The normal build tree installs only the declared shared package.
- A second static tree compiles every upstream test target but installs nothing.
- Native builds execute CTest; cross builds record compilation/link evidence and
  explicitly report that target execution was skipped.
- The package contains no test-only `.a` files or executables.

## Symptom And Root Cause

For LevelDB 1.23, `BUILD_SHARED_LIBS=ON` creates only 8 public-API tests. Another
22 tests access internal implementation symbols and are enclosed by
`if(NOT BUILD_SHARED_LIBS)`. Changing the package to static would make those
tests available, but would no longer validate the required shared artifact.
Disabling tests would remove most upstream coverage.

The release archive also omits googletest and benchmark submodule contents, so
the test tree is not reproducible unless the pinned commits are fetched and
verified separately.

## Implementation

Keep the package build conventional:

```python
import os

from conan.tools.build import can_run


def generate(self):
    tc = CMakeToolchain(self)
    tc.cache_variables["BUILD_SHARED_LIBS"] = True
    tc.cache_variables["PROJECT_BUILD_TESTS"] = False
    tc.cache_variables["PROJECT_INSTALL"] = True
    tc.generate()

def build(self):
    cmake = CMake(self)
    cmake.configure()
    cmake.build()
    self._build_upstream_tests()
```

Create the test-only tree with the same toolchain:

```python
def _build_upstream_tests(self):
    test_dir = os.path.join(self.build_folder, "upstream-tests")
    toolchain = os.path.join(self.generators_folder, "conan_toolchain.cmake")
    self.run(
        f'cmake -S "{self.source_folder}" -B "{test_dir}" '
        f'-DCMAKE_TOOLCHAIN_FILE="{toolchain}" '
        '-DBUILD_SHARED_LIBS=OFF '
        '-DPROJECT_BUILD_TESTS=ON '
        '-DPROJECT_INSTALL=OFF'
    )
    self.run(f'cmake --build "{test_dir}" --parallel')
    if not can_run(self):
        self.output.info("upstream tests compiled but cannot run")
    else:
        self.run("ctest --output-on-failure --no-tests=error", cwd=test_dir)
```

Map `PROJECT_BUILD_TESTS` and `PROJECT_INSTALL` to the actual upstream option
names. If the project has no install-disable switch, use an equivalent
test-only configuration and verify that `package()` installs only from the
normal build tree.

## Forbidden Approaches

- Do not change the formal package to static only to make tests link.
- Do not disable or delete upstream tests because the local machine cannot run
  target binaries.
- Do not claim CTest passed when `can_run()` is false and execution was skipped.
- Do not package the test-only static library, googletest, benchmark, or test
  executables.
- Do not fetch moving submodule branches or unverified source archives.

## Verification

1. Force a source rebuild with `--build=<package>/*`.
2. Confirm the second tree builds the expected number of upstream test targets.
3. On a native target, run CTest with `--no-tests=error` and require all tests
   to pass. On a cross build, state only that targets compiled and linked.
4. Run a real Conan consumer against the packaged shared target.
5. Inspect the package: expected shared library and headers only, no `.a`, test
   executable, test dependency, or host path.
6. Inspect representative test ELFs. Static-test executables must not list the
   packaged shared library in `NEEDED`.

## Validated Example

LevelDB 1.23, verified through 2026-07-24:

- main shared build completed 42/42 steps;
- test-only static build completed 160/160 steps and produced all 30 POSIX
  upstream test executables;
- a real consumer compiled and linked Put/Get/WriteBatch/Delete operations;
- the package contained 15 public headers, `libleveldb.so.1.23.0` and its names,
  no static archive, and no packaged tool;
- the shared library was AArch64 ELF64 with SONAME `libleveldb.so.1` and RUNPATH
  `$ORIGIN`;
- cross-build execution was correctly skipped because `can_run` was false;
- on a HarmonyOS PC AArch64 device, all 30 upstream test executables and the
  packaged shared-library consumer passed (31/31 executable targets).
