# E225：CMakeToolchain source-side preset 与 Conan test-package 临时布局

## 知识类型
新增知识草稿，不预占正式 E 编号。

## 扩展目标/正式未命中证据
绑定基线存在 test_package、CMakeDeps 等相邻草稿，但未命中“CMakeToolchain source-side preset 与标准 `conan create` 下由 Conan 自主管理每次调用唯一临时布局”的正式知识。旧草稿把外部 `BUILD_DIR` 当成必须契约，官方 CI #15728 证明该前提错误。

## 通用问题
CMakeToolchain 即使使用 out-of-source build/generators，仍可能向 test_package source 写 `CMakeUserPresets.json`，因此必须设置 `user_presets_path=False`。布局本身不应依赖非标准 shell `BUILD_DIR`；Conan 2.29.1 对 test-package 的 `build_folder="$TMP"` 使用 `tempfile.mkdtemp()` 创建遵循 `TMPDIR` 的每次调用唯一目录。

## 错误指纹
`test_package/CMakeUserPresets.json`、`Invalid configuration: Poly/ML test_package requires external BUILD_DIR before generators run`。后者是 recipe 非标准环境依赖导致的官方 CI 失败，而不是推荐的 fail-closed 行为。

## 根因模型
核心根因链为两部分：CMakeToolchain 默认 user preset 行为可能写回 source；recipe 将本地 launcher 的 `BUILD_DIR` 误当 Conan 标准契约，导致官方标准 `conan create` 无变量时在 test_package layout 失败。正确闭环是禁用 user preset，并由 Conan `$TMP` 自主管理唯一临时根。

## 适用范围
使用 Conan 2 `test_package` 和 CMakeToolchain，并要求 source 零生成物、标准 `conan create` 可直接运行的配方。

## 不可泛化边界

`$TMP` 是 Conan test-package layout 的特殊值，不是 shell 环境变量；当前正向证据严格绑定 Conan 2.29.1。不得仅凭文档或版本号推断其他版本等价，采用前必须在目标 Conan 版本以显式 unset `BUILD_DIR` 的 `conan graph info`/`conan test` 探针确认：临时根由 Conan 创建、遵循可写 `TMPDIR`、build/generators 位于 source 外，并且 source 不生成 preset。若探针不满足，应使用该版本正式支持且已实测的 test-folder 配置，不得恢复 recipe 对私有环境变量的依赖。

## FAIL→修复→PASS

Poly/ML Round 15 主测试成功但门禁发现 source-side `CMakeUserPresets.json`；设置 `user_presets_path=False` 后零污染。随后采用“缺少外部 `BUILD_DIR` 就在 generators 前 fail-closed”的方案，并由本地 launcher 注入该变量，使 Round 16/17 PASS。该 fail-closed 只能保留为错误历史与错误指纹，不能作为推荐：它把本地 launcher 私有约定误当成标准 `conan create` 契约，掩盖了配方不可独立运行的问题。

官方 CI #15728 使用标准 `conan create`，没有该变量，test_package 在 layout 阶段抛 `ConanInvalidConfiguration`，因此失败。最终修复删除 `os`/`ConanInvalidConfiguration` 和外部变量逻辑，改用 `cmake_layout(self, build_folder="$TMP")`。Conan 2.29.1 实测将 `$TMP` 解析为 `tempfile.mkdtemp()` 创建的唯一目录，并遵循 `TMPDIR`；保留 `tc.user_presets_path=False`，从生成源头阻止 preset 写回 source。Round 18 的独立 graph/test 探针在 recipe/test_package 执行层显式 unset `BUILD_DIR` 后通过，完整 CI exit 0。

## 禁止模式
禁止用 `.gitignore` 或生成后删除代替 `user_presets_path=False`；禁止 recipe 硬依赖 CI launcher 私有 `BUILD_DIR`；禁止把 `$TMP` 当 shell 变量手动展开；禁止未经目标 Conan 版本实测就泛化该特殊值。

## 证据来源

Round 15 source 污染证据、Round 16/17 本地 launcher 注入 `BUILD_DIR` 的 PASS、官方 CI #15728 标准 `conan create` 无变量 FAIL、Conan 2.29.1 `cmake_layout` 源码与 Round 18 独立无变量探针/完整 CI PASS。Round 18 权威日志 SHA-256 为 `22956abc952e846be7cffa1bba34a480e84c401ef0f05cc9740c65b451abbe6a`。

## CI launcher 与 recipe 边界

当前基线 `ci/conan/build_and_test.sh:749` 的预下载实现自身仍在命令作用域读取 `BUILD_DIR`。Round 18 完整入口为该 launcher 提供可写工作目录，但在进入 Conan recipe/test_package 语义前不把它作为配方契约；独立 graph/test 探针已显式 unset `BUILD_DIR` 并通过。该基础设施边界可以作为运行证据说明，不能混写成 recipe 仍依赖 `BUILD_DIR`，也不能反过来声称当前 launcher 已完全不需要该变量。
