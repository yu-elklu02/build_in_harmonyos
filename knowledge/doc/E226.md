# E226 - Read `os.popen` child output as bytes on HarmonyOS Python 3.12

## Symptom

A native executable launches and writes output, but the Python test driver
fails while reading its pipe, before it can evaluate the child status:

```text
process_output = pipe.read()
TypeError: can't concat str to bytes
```

JsonCpp 1.9.8 reproduced this in both parser/writer CTest entries on the first
JSON input. Its independently linked unit executable still passed, proving
that this was a Python output-capture failure rather than a library failure.

## Root Cause

In the validated HarmonyOS Python 3.12 build, the text wrapper returned by
`os.popen()` feeds a `str` fragment into an incremental codec path that expects
bytes. `pipe.read()` therefore raises `TypeError` before returning any output.
Changing locale or catching the exception cannot recover the lost child status
and would allow an unexecuted test suite to appear successful.

This is distinct from E055. E055 covers behavioral differences in
`posix_spawn`; E226 covers the text-decoding layer after a child was launched.

## Fix

Keep the same upstream command and failure check, but bypass the faulty text
wrapper. Capture stdout/stderr as bytes and decode once after `communicate()`:

```python
process = subprocess.Popen(
    cmd,
    shell=True,
    stdout=subprocess.PIPE,
    stderr=subprocess.STDOUT,
)
process_output = process.communicate()[0].decode(
    "utf-8", errors="replace"
)
status = process.returncode
```

For callers that only test status truthiness, return code `0` preserves the
successful behavior of `os.popen().close()` returning `None`; nonzero remains
a failure. Do not change test inputs, expected output, or case registration.

## Forbidden Workarounds

- Do not catch `TypeError` and report success.
- Do not disable the affected CTest entries.
- Do not skip inputs that reached this output-capture path.
- Do not count assertions, writer-mode reruns, or CTest wrappers as new cases.
