# E321 知识草稿：消费方 meson 检测 gobject-2.0 需配方补转发型 .pc

> 编号：E321（草稿，待 graph promote 转正式；E160 编号已被占用，按设备端最大 E 编号 E320 顺延）
> 文件名：E321-draft-gobject2-pc-forwarding
> 实例来源：graphene 1.10.8（archives/g/graphene/1.10.8）→ 依赖 glib2/2.88.0
> 检索字段：library=graphene / build=meson / error=pkgerror / toolchain=clang15 / platform=ohos / dependency=glib2

## 症状

消费方配方（meson 构建）在 generate() 执行 `PkgConfigDeps(self).generate()` 后，
meson configure 阶段失败：

```
Run-time dependency gobject-2.0 found: NO
```

或 pkg-config 报：

```
No package 'gobject-2.0' found
```

即 `meson.build` 里 `dependency('gobject-2.0')` 检测不到，构建中止在配置阶段。

## 根因

Conan 2 的 `PkgConfigDeps.generate()` 只为每个依赖包生成其 `package_info()` 里
`pkg_config_name` 声明的**那一个** .pc 文件。本仓 glib2 配方
（archives/g/glib2/2.88.0）只声明 `pkg_config_name = "glib-2.0"`，所以 PkgConfigDeps
只生成 `glib-2.0.pc`。

但 GNOME/GLib 家族上游是 .pc **多文件体系**：glib 2.88.0 上游安装会落
`glib-2.0.pc`、`gobject-2.0.pc`、`gio-2.0.pc` 等多个 .pc。消费方
（graphene 1.10.8）的 graphene-gobject 类型按上游惯例用
`dependency('gobject-2.0')` 检测 gobject，于是 pkg-config 在 generators 目录
搜不到 `gobject-2.0.pc` → 检测失败。

这是「conan PkgConfigDeps 每包单 .pc 输出」与「上游多 .pc 体系」之间的**通用落差**：
任何消费方用 meson 检测 glib 家族的非主 .pc（gobject-2.0 / gio-2.0 /
gmodule-2.0 …）都会撞上，非 graphene 独有。

## 修复方案

在**消费方配方**的 `generate()` 里，`PkgConfigDeps.generate()` 之后补一个
**转发型 .pc**：

- 文件名：消费方要检测的副 .pc 名（如 `gobject-2.0.pc`）
- 落盘位置：`self.generators_folder`（PkgConfigDeps 输出同目录，meson 的
  pkg-config 自动搜索该目录）
- 内容四行：`Name:` / `Description:` / `Version:` / `Requires: glib-2.0`
  - `Version` 从主 .pc（`glib-2.0.pc`）的 `Version:` 行**动态继承**，不写死
  - 转发型 .pc **不写** prefix / Cflags / Libs —— 路径信息全部由被转发的
    `glib-2.0.pc` 提供（Requires 带入）
- 前提：依赖声明用 `transitive_headers=True, transitive_libs=True`，让 glib
  的头/库随消费方透传给下游（graphene-gobject 静态链接需 gobject 符号）

同手法：仓内 pango 1.56.4 配方【skill: --alias-pc 生成】
（cairo-ft=cairo,freetype2 / cairo-fc=cairo,fontconfig）；另见 gdk-pixbuf
`_create_pkg_config_alias`（复制改名式别名，gdk-pixbuf/conanfile.py L292-308）。

## 实例：graphene 1.10.8 配方 `_forward_gobject_pc`

```python
def _forward_gobject_pc(self):
    _src = os.path.join(self.generators_folder, "glib-2.0.pc")
    if not os.path.isfile(_src):
        self.output.warning("gobject-2.0 forward: glib-2.0.pc not generated, skip")
        return
    _ver = "0"
    with open(_src, encoding="utf-8") as _f:
        for _line in _f:
            if _line.startswith("Version:"):
                _ver = _line.split(":", 1)[1].strip()
                break
    _dst = os.path.join(self.generators_folder, "gobject-2.0.pc")
    if os.path.isfile(_dst):
        return
    with open(_dst, "w", encoding="utf-8") as _f:
        _f.write(
            "Name: gobject-2.0\n"
            "Description: forwarding .pc generated by graphene recipe (Requires glib-2.0)\n"
            "Version: %s\n"
            "Requires: glib-2.0\n" % _ver
        )
```

调用链：`generate()` → `PkgConfigDeps(self).generate()` → `self._forward_gobject_pc()`。

配置阶段真机证据（设备端 build-round-01.log）：

```
graphene/1.10.8: pkg-config evidence: glib-2.0.pc Version: 2.88.0
Run-time dependency gobject-2.0 found: YES 2.88.0
Found pkg-config: YES (/data/service/hnp/bin/pkg-config) 0.29.2
```

CI 结果：21/21 测试 PASS（18 graphene + 3 mutest），graphene-gobject 类型真实编译
（graphene-gobject.c.o 编译、graphene-gobject-1.0.pc 安装）。

## 禁忌

1. **写死 Version**（forbid_1）：转发型 .pc 里硬编码 `Version: 2.88.0`。依赖升级或
   配方复用到其他版本时与主 .pc 脱节，消费方 `dependency(..., version: '>=X')`
   约束会拒绝。必须从主 .pc 动态继承。
2. **把包内 .pc 直接加 PKG_CONFIG_PATH**（forbid_2）：conan 包内自带的 .pc 按
   `prefix=/` 安装，写的是 /lib、/include 等根路径；直接加 PKG_CONFIG_PATH 会
   解析到设备上不存在的 /lib。应改为转发型 .pc 指向 conan 生成的 glib-2.0.pc；
   同时不要混设 C_INCLUDE_PATH（见 E075 / P014）。

## 环境前置提示（OHOS 设备）

- OHOS 设备 PATH 可能**没有 meson 可执行文件**。按仓内 `archives/m/meson/1.5.1`
  版本安装：

  ```bash
  python3 -m pip install --user meson==1.5.1
  ```

  落 `~/.local/bin/meson`（确保 PATH 含 `$HOME/.local/bin`）。1.5.1 满足 glib2
  配方（meson ≥ 1.4）与 graphene meson.build（≥ 0.55.3）。
- 转发型 .pc 必须与 PkgConfigDeps 输出**同目录**（self.generators_folder）。
- 若配置阶段另报 `llvm-ar`/`llvm-ranlib` 找不到（OHOS clang 工具链在
  /data/service/hnp/bin，PATH 无裸名），参考 graphene 配方 `_inject_meson_archiver`
  （把 ar/ranlib 全路径注入 conan_meson_native.ini，不污染 PATH）。
