# E326 — OHOS hmmac 沙盒拒绝 make 默认 SHELL=/bin/sh（/bin/sh: Permission denied → Error 127；配置阶段 try-compile 与编译阶段均受影响，改用 Ninja generator 解决）

## 错误特征

conan create / make 编译 CMake 工程时，所有编译目标静默失败，日志特征：

```
make[3]: /bin/sh: Permission denied
make[3]: *** [CMakeFiles/xxx.dir/xxx.c.o]: Error 127
make[2]: *** [CMakeFiles/xxx.dir/all]: Error 2
make[1]: *** [CMakeFiles/xxx.dir/rule]: Error 2
make: *** [all]: Error 2
```

**CMake 配置阶段同样失败**（干净构建在配置阶段即中止）：

```
-- Check for working C compiler: /data/service/hnp/bin/clang ... broken
make[1]: /bin/sh: Permission denied
make[1]: *** [CMakeFiles/cmTC_xxxxx.dir/build.make:...: ...] Error 127
```

或表现为 `Error 1`，且 clang/clang++ 编译命令**零输出**（编译器根本没被启动，因为负责启动它的 /bin/sh 就被拒绝）。

## 触发条件

- 构建系统: cmake（Unix Makefiles generator 生成 Makefile 时硬编码 `SHELL = /bin/sh`）
- 阶段: **configuration（try-compile）+ compilation（make）**
- 环境: OHOS OpenDesk 沙盒（hmmac 策略拒绝执行 /bin/sh）

## 根因分析

CMake 生成的 Makefile 硬编码 `SHELL = /bin/sh`（通常在 Makefile 第 48 行附近）。make 子进程执行每条编译规则时，会用该 SHELL 启动命令行。本机 OHOS OpenDesk 沙盒的 hmmac 策略**拒绝执行 /bin/sh**，报 `/bin/sh: Permission denied`，导致所有编译目标返回 Error 127 / Error 1。

**该问题影响两个阶段**：
1. **编译阶段**：make 执行 .o 编译规则时调用 /bin/sh。
2. **CMake 配置阶段（cmake -B）的 try_compile**：如 `Check for working C compiler` 内部也调用 make + /bin/sh → try-compile 失败 → `-- Check for working C compiler ... broken` → 干净构建在配置阶段就中止。**只修复 cmake --build 的 SHELL 覆盖无法解决配置阶段失败**（配置阶段 try-compile 的 make 不受命令行 SHELL 覆盖影响）。

补充：hmmac 还拒绝 **symlink() 系统调用**（`ln -s`、`cmake -E create_symlink`、`cmake -E cmake_symlink_library` 全部 Permission denied），共享库 VERSION/SOVERSION 的版本化 symlink 规则需改写为 cp 复制。

注意：这不是 clang 前端初始化失败，也不是 LD_LIBRARY_PATH 问题。SDK clang/clang++（含交叉 aarch64-unknown-linux-ohos-clang）编译本身完全正常（-E/-c/-fsyntax-only exit=0）。日志中"clang 零输出"实际是 make 子进程调用 /bin/sh 无法启动所致。

## 解决方案

### 推荐方案（首选，主编验证 + 实测通过）

**改用 Ninja generator**：cmake -B 配置命令追加 `-G Ninja -DCMAKE_MAKE_PROGRAM=/data/service/hnp/bin/ninja`。Ninja 直接 exec 编译器，不经 /bin/sh，**配置阶段 try-compile 与编译阶段均通过**。

```python
def _ninja_bin(self):
    candidates = ["/data/service/hnp/bin/ninja", shutil.which("ninja")]
    for c in candidates:
        if c and os.path.isfile(c):
            return c
    raise ConanInvalidConfiguration("找不到 ninja")

# 配置阶段（关键）：追加 -G Ninja
self._run_sp('{cm} -B "{bd}" -S "{src}" -G Ninja -DCMAKE_MAKE_PROGRAM={ninja} {defs}'.format(...))
# 编译阶段：ninja 直接 exec 编译器，无需 SHELL 覆盖
self._run_sp('{cm} --build "{bd}" -j{nj}'.format(...))   # ⚠️ 勿加 -- SHELL=...（Ninja 报 unknown target）
```

配套修复（Ninja 下必须）：
1. **共享库 symlink 规则补丁**：Ninja 下 symlink 规则位于 `build-ohos/CMakeFiles/rules.ninja`：
   ```
   rule CMAKE_SYMLINK_LIBRARY
     command = <cmake> -E cmake_symlink_library $in $SONAME $out && ...
   ```
   改写 command 为 `for f in $out; do cp -f $in $$f; done`（$out 多输出循环复制），
   产物为独立文件而非符号链接（hmmac 拒绝 symlink() 系统调用）。
2. **`cmake --build` 不可追加 `-- SHELL=...`**：Ninja 会把 `SHELL=/data/service/hnp/bin/bash`
   当作 ninja target，报 `ninja: error: unknown target 'SHELL=/data/service/hnp/bin/bash'`。
   Ninja 不需要 SHELL 覆盖（不经 /bin/sh）；`os.environ["SHELL"]` 保留为无副作用兜底。

R33 合规：ninja 路径为显式探测常量，不依赖未定义 shell 变量。

### 回退方案（仅 Makefiles generator 场景）

若无法切换到 Ninja，则编译阶段用 `cmake --build ... -- SHELL=/data/service/hnp/bin/bash`
（make 命令行变量优先级最高，覆盖 Makefile 硬编码值）。**注意**：该方案不能修复
CMake 配置阶段 try-compile（其内部 make 不受命令行覆盖），干净构建仍可能在配置阶段失败，
仅作 make-only 场景的降级兜底。

```python
_MAKE_SHELL = "/data/service/hnp/bin/bash"
os.environ["SHELL"] = _MAKE_SHELL   # 环境变量兜底
self.run('{cm} --build "{bd}" -j{nj} -- SHELL={shell}'.format(
    cm=cmake, bd=bdir, nj=os.cpu_count() or 4, shell=_MAKE_SHELL))
```

### 禁止做法

- ❌ 不要误判为"clang 前端初始化失败/沙盒 mmap 限制"而放弃本机编译验证（clang 编译正常，真正问题是 make 的 SHELL）。
- ❌ 不要通过修改 CMake 生成的 Makefile 硬编码 SHELL（每次 cmake 配置会重新生成，且污染配方）。
- ❌ 不要在 build() 中裸用 `${SHELL}` 等未定义 shell 环境变量（R33）。
- ❌ 不要只在 cmake --build 修 SHELL 而忽略配置阶段 try-compile（干净构建仍会在配置阶段失败）。

## 验证

```bash
grep -n '^SHELL' build-ohos/Makefile            # 应看到 SHELL = /bin/sh（复现点，Makefiles 下）
# 复现配置阶段失败：
cmake -B build-ohos -S . ...                     # 默认 Makefiles → Check for working C compiler ... broken
# 修复验证（Ninja）：
cmake -B build-ohos -S . -G Ninja -DCMAKE_MAKE_PROGRAM=/data/service/hnp/bin/ninja ...
ninja -C build-ohos                               # 多个 .o 成功生成，配置阶段 try-compile 通过
# conanfile.py 修改后：
conan create <recipe> -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing
# 确认 symlink 补丁：
grep -A2 "rule CMAKE_SYMLINK_LIBRARY" build-ohos/CMakeFiles/rules.ninja   # command 应为 cp 循环
```
